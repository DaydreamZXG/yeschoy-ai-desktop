## 1. 产品怎么理解

野菜桌面助手不是又一个 AI 聊天窗口，也不是 CC Switch 那种极客切供应商工具。它是 **野菜API 的安装器和遥控器**：

1. 登录野菜账户。
2. 看见这台电脑上的应用。
3. 没装 Claude / Codex → 从野菜镜像装（没梯子也能下）。WorkBuddy 没装 → 打开官网 `https://www.workbuddy.cn/`，不镜像、不静默装。
4. 已装 → 选模型和价格，一键写入，打开应用。
5. 账单里能看到请求。
6. 退出/恢复能拿回野菜改过的设置。

侧栏现在只有三件事：**我的应用、用量账单、设置**。界面只走简体中文。

WorkBuddy 是第六个一键接入目标，不是第七套安装镜像。作者明确决定：WorkBuddy 走官网即可。

## 2. 当前能用的能力

- WorkBuddy 一键接入：直接写 `~/.workbuddy/models.json`，不走本地网关，不强制重启，不改默认模型。
- 热加载：已运行则聚焦/不重复拉起；用户在**新对话**里自己选野菜模型。
- 失败回滚；退出助手 / 退出账号走现有恢复体系。
- Codex 历史接管改为流式改写，且 `begin()` 只建清单、真正改 session 在 `commit()`。
- Claude / Codex 安装：公网 catalog 失败后走直连 DNS（`ergou.qzz.io` → 编译期地址）。
- DSH 源码构建校验流水线在 `deploy/dsh-source-build/`。
- 界面：语言切换已砍；模型价格 / 连接诊断 / 本机扫描收到设置「排查与高级」；即将支持卡从首页拿掉。

## 4. WorkBuddy 接入要点

配置：`~/.workbuddy/models.json`。兼容根为数组，或带 `models` / `availableModels` 的对象。畸形 JSON 失败关闭，不猜着修、不整文件覆盖。

野菜维护的字段：`id` / `name` / `vendor=野菜API` / `url` / `apiKey` / `useCustomProtocol` / 工具与视觉能力 / `maxInputTokens` / `maxOutputTokens`。  
请求地址：`{origin}/v1/chat/completions`。拒绝 localhost。

保留其他厂商模型和未知字段。每个模型用自己的 key。写入走 `FileTransaction`。

发现：

- macOS Bundle ID：`com.tencent.workbuddy.mac`（本机实测 Team ID `FN2V63AD2J`，仅作发现/安装身份参考，当前不走镜像安装）。
- Windows：包名 `Tencent.WorkBuddy` 或产品名 `WorkBuddy`；EXE 公司名为 Tencent 或含「腾讯」；卸载项允许 publisher 为空或腾讯，拒绝 Contoso 和 `WorkBuddy Helper`。

## 7. 最新整体审查（相对 `origin/product/yeschoy-v1`）

记录：`/var/folders/zw/z2s69k4n4k1dfgxk37lkn09w0000gn/T/grok-zxg/grok-review-a678ed2c.md`  
结论：**还不能发。3 个缺陷，1 个建议。**

先前修过且仍然成立：对象包装目录的 husk 删除、`availableModels` 清理、腾讯/NSIS 身份、WorkBuddy 走官网、首页仍能接入和恢复。

**必须先修：**

1. **首次接入写成顶层数组后，热加载再退出，恢复会空成功、key 还在。**  
   `connection_recovery.rs` 的 `restore_bytes` 把缺失的 `before` 变成 `{}`，数组目录走不进整对象删除。空文件首次写入就是数组。要补：`before=None`、`after=[野菜…]`、`current` 带 `temperature` 或额外用户模型的 fixture。

2. **Codex 历史仍在打开 Codex 之后才 `commit()`。**  
   应在 `prepared.commit()` 之后、`open_and_wait` 之前改写 session。现在进程已经按 `openai` 把对话读进来，sqlite 还可能被锁。

3. **`is_running` 失败时仍会再拉起进程。**  
   `open_unless_running` 把错误当成没在跑。Windows 上会再 `CreateProcess`。失败应收口或报状态不可用。  
   现有「已运行不 spawn」测试走的是生产路径用不到的私有函数，不能当真覆盖。

真机仍未做：Windows/macOS 隔离 Home 的发现、热加载、请求 URL、`useCustomProtocol` 是否二次拼接、能力字段是否跟打包目录走。
