# 野菜 API 接入体验审计

审计范围：应用接入页的首次接入、运行中应用交接、日常打开、更新接入、后台刷新、失败恢复，以及 Codex Desktop、Claude Desktop、Claude Code、Pi、Hermes、OpenClaw、DSH web 的表面差异。此次修复源代码与测试，并生成编译产物和隔离 Windows QA 产物；不打包正式版本、不上传、不发布更新。

## 结论

用户看到的“客户端完全卡死”有多条明确代码原因，不是单纯机器慢：旧版确认弹窗曾覆盖完整异步任务；Windows 主窗口退出后残留的后台进程会让接入持续等待；接入 IPC 没有渲染层最终截止时间；旧 Codex 配置还会在每次启动时重新拉起整个野菜 GUI 程序读取令牌，容易被 Defender 或冷启动拖过 Codex 的认证时限。Codex Logo 卡住则是本机网关未就绪、认证助手超时或配置无法加载时缺少启动前校验的综合表现。后续真实用户反馈还证明，原来的 Windows 冒烟只验证了安装、启动和退出，不能证明接入后的本地网关会在长会话中持续存活；该结论现已更正，持续网关生命周期被列为独立发布门槛。

## 生命周期规则

| 表面                                 | 接入或更新时                                                                                               | 打开使用时                                                                       |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Codex Desktop / Claude Desktop       | 若正在运行，先提醒保存；确认后先请求正常退出；Windows 只对精确安装路径的残留进程做受控结束；配置完成再重开 | 只启动应用和已有本地连接，不重写设置，不发送付费测试请求；Codex 会先验证本机网关 |
| Claude Code / Pi / Hermes / OpenClaw | 不关闭正在运行的命令行；设置由新终端会话读取                                                               | 打开一个新终端会话                                                               |
| DSH web                              | 保存现有 DSH 接入配置，不套用桌面进程退出规则                                                              | 启动本地服务并在浏览器中打开                                                     |

## 新的动作层级

1. 未接入：唯一主动作是“一键接入”或“安装并接入”。
2. 已接入：主动作是“打开使用”；次动作是始终可见的“更新接入设置”。
3. 应用正在运行：先出现保存提示；确认后提示立即消失，接入进度回到页面内展示。
4. 打开超时：页面恢复可点击状态，说明应用仍可能稍后打开，并允许重试或查看接入设置。
5. 后台刷新失败：保留上一份可用设置，不用默认值覆盖；显示可重试提醒，但不锁死接入动作。
6. 接入超过 90 秒：页面恢复可操作并通知原生端安全取消；清理完成前的重复接入立即返回“正在收尾”。
7. 首次应用扫描失败：主按钮直接变为“重新检查应用”，并说明重试只做只读检查、不修改设置。
8. 首次接入状态读取失败：主按钮直接变为“重新读取接入状态”，未读取成功前不冒险覆盖已有配置。

## 仍需真机验证的项目

- Windows 10：补充低版本系统与旧 WebView2 场景；Windows 11 的安装、升级、后台退出、可见重启与 Codex 国内源安装已在干净虚拟机验证。
- Windows 已登录业务账号的隔离机：确认 Codex 使用 `experimental_bearer_token` 访问 127.0.0.1 网关、保留官方登录展示但请求不走官方计费；连续发送多轮真实请求，并在中途模拟监听异常和网络抖动。干净机未放入真实业务凭据，因此此前的安装冒烟不能作为这项验证的替代品。
- macOS Intel 与 Apple Silicon：Codex Desktop 和 Claude Desktop 的正常退出及自动重开。
- 七个应用分别验证“打开使用”不会重写配置；终端 Agent 不影响已有会话；DSH 能打开浏览器。
- 人工连续操作：打开应用期间切换导航、更新接入、窗口失焦再聚焦，确认没有透明遮罩或永久 disabled。

以上是余下的发布前验收项，不代表业务账号链路已经完成跨平台验收；QA 产物不得作为官网正式包上传。

## 本轮真实环境结果

- Windows 11 25H2 中文干净虚拟机：旧版后台进程可被安装器识别并正常结束，静默升级后新窗口可见，关闭窗口可选择后台运行或彻底退出，再次启动正常。
- Windows 干净机暴露出动态依赖 `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll` 导致首启即退；已改为静态 CRT，重建后首次启动通过。
- Codex Desktop 约 760 MB 的 Windows 原版包从 `ergou.qzz.io` 国内镜像完整下载，进入 Windows 系统安装器验签，安装后首次启动并被野菜重新识别。
- macOS Intel 此前的代码快照已完成生产模式 `.app` 构建；用户明确要求后已停止并不再进行本机 GUI/接入验证，未触发关闭 Codex 或写入本机配置。最新源码仅做编译和自动化检查，未生成可发布 Mac 包。
