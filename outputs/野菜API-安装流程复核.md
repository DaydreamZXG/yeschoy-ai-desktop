# 野菜 API 安装流程复核

2026-09-06 · RU-051 · 客户端仍为 0.4.8，未打包、推送或发布。

## 本轮改动

- Codex 检测采用应用标识，不再仅凭普通 ChatGPT 的文件名认定已安装。实际安装位置被同名文件、损坏目录或链接占用时，保留原内容并解释冲突；独占发布仍不覆盖用户文件。
- 下载期间切换应用，前一任务成功、失败或取消后，自动恢复当前应用的安装入口。第一次进入、返回页面和迟到响应也纳入测试。“我已安装，重新检查”同时刷新安装进度与应用发现，不会重复启动安装。
- Windows 无需登录即可检查安装结果；未装好可以再次检查。安装完成不等于接入成功。开始安装后退出账户、之后重新登录，也不会复活旧接入许可。匹配本次账户、模型、分组和安装目标的明确确认，才会继续接入一次。
- 旧首页的 7 条失效集成测试改为当前完整 App 的 9 条真实视图/状态管理/IPC 解码流程。独立的供应商、Pi、OpenClaw、Skills 和同步组件测试仍保留，没有跳过失败用例。
- 保留原有绿色品牌样式，检查了浅色与深色预览；主要动作明确区分“检查安装结果”和“检查安装并继续”，不把内部状态名交给用户。

## 下载源与实机边界

| 项目 | 2026-09-06 实际观察 | 尚缺证据 |
| --- | --- | --- |
| ergou.qzz.io | HTTPS 健康检查可直连，`origin_ready` | 大陆不同运营商客户端下载链路 |
| 定时同步 | 服务器 timer 正在运行；5 个源已暂存，尚未完成全部平台验证 | 验证后供客户使用的下载发布流程 |
| Claude Mac 包 | 官网返回浏览器验证要求，自动同步仍失败 | 合法可用的官方下载通路，不能绕过安全验证 |
| 公共第三方安装源 | 健康检查为 `thirdPartyInstallersPublished: false` | 厂商允许面向客户再分发的依据，不能把企业内部部署文档等同于公开镜像许可 |
| 野菜更新源 | `updatesPublished: false` | 后续发布经签名的版本与更新清单；本轮不发布安装包 |
| Windows / 苹果芯片 Mac | 当前宿主为 Intel Mac，可交叉编译 | 干净系统上的下载、安装、首次启动和接入实测 |

Windows 系统安装有明确的用户确认步骤；不静默提权、不关闭系统安全检查。其他五款客户端当前是官方安装引导，不宣称已经全部无人值守安装。

另外，Windows 保留至多两个可能仍被系统安装器使用的版本；不会自动删除它们。缓存满时当前提供官方安装与回来检查的替代入口，不能声称完成安装就会自动释放缓存。该限制已从原先误导性的提示中说明清楚，仍不是完善的缓存管理体验。

官方依据：[OpenAI Windows 企业部署说明](https://learn.chatgpt.com/docs/enterprise/windows-deployment)、[Claude Windows 部署说明](https://support.claude.com/en/articles/12622703-deploy-claude-desktop-for-windows)、[Claude 官方下载页](https://claude.com/download)。

## 实机验收清单

使用可恢复的干净测试用户，不替换日常应用或登录凭据。先在 Windows 标准用户与 Apple Silicon Mac 分别验证未登录下载/安装/确认，再验证登录后安装并接入；记录应用版本、系统版本、真实下载源、安装确认和首条模型回复。随后验证取消下载、暂时离线重试、切换应用、恢复原设置及退出野菜。任何一步失败都保留正确状态和重试入口，不能以构建通过替代这些结果。
