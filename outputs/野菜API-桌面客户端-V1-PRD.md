# 野菜API 官方桌面客户端 V1 PRD

状态：产品草案，未进入架构冻结或开发  
日期：2026-08-29  
产品名称：野菜API  
建议英文标识：YesChoy  
正式应用标识：`com.yeschoy.desktop`（已确认）

## 1. 产品定义

野菜API 桌面客户端是一款面向普通用户的官方 AI 配置助手。它把账号、余额、用量、模型和价格，与用户电脑上已经安装的 AI 工具连接起来，让不了解 API Key、Base URL 和配置文件的人也能完成配置并开始使用。

它不是一个通用 API 配置编辑器，也不是另一个要求用户理解服务商、协议和环境变量的 CC Switch 界面。

一句话定位：**登录野菜账号，一键配置已经安装的 AI 工具。**

## 2. 最核心解决的三个问题

### 2.1 不知道怎样把账号变成可用工具

用户在网站有账号和余额，但不知道从哪里创建 Key、Base URL 填什么、模型名是什么、配置文件在哪里。

目标结果：客户端完成账号授权、工具发现、线路和模型选择、配置写入与验证。

### 2.2 配置容易出错，也不敢修改

配置可能涉及 JSON、TOML、YAML、环境变量和不同协议；误写可能破坏用户原有配置。

目标结果：每次变更前创建加密的临时回滚快照，只修改野菜API拥有的字段，写后校验，失败自动恢复；成功或恢复完成后立即删除快照，不保留历史备份。

### 2.3 不知道模型差别、价格和失败原因

用户面对大量模型 ID，不知道兼容哪个工具、官网多少钱、本站实际多少钱，也无法区分网络、余额、模型或配置问题。

目标结果：显示真实模型 ID、兼容性、推荐标签和同口径价格对比，并给出分层诊断与安全修复。

## 3. 目标用户与边界

### 3.1 V1 目标用户（已确认）

- 已经安装至少一种受支持 AI 工具。
- 不熟悉 API Key、Base URL、模型协议和本地配置文件。
- 希望查看野菜API余额、用量、价格并快速开始使用。

### 3.2 V1 首批工具（已确认）

1. Claude Code
2. Codex
3. Pi
4. DSH（DeepSeek Harness，仅 `web` profile 自动配置；其他 profile 只读发现）

OpenCode 标注为「即将支持」（2026-09-13 决策）：V1 保留只读发现，一键接入适配器移至后续版本排期。Hermes、OpenClaw 不属于 V1 工具范围（2026-09-13 决策移出），客户端不为它们提供接入入口；既有实现代码随遗留清理批次摘除。

### 3.3 V1 明确不做

- 不自动下载、安装、升级或卸载第三方 AI 工具。
- 不做任意 API 服务商管理和复杂代理编排。
- 不做插件市场、MCP/Skill 市场和多服务商切换中心。
- 不在客户端重复实现支付结算；充值打开野菜API网页钱包。
- 当前阶段不修改 NewAPI、服务器、Nginx、DNS、数据库或线上配置。
- 不宣称支持 Cherry Studio、Cline、WorkBuddy 等尚未完成适配和验证的工具。

## 4. 产品原则

1. **结果优先**：默认展示“可使用、需要修复、余额不足”，而不是配置文件字段。
2. **透明但不强迫理解**：真实模型 ID、线路地址和变更文件可以查看；普通流程不要求手动输入。
3. **自动但不偷偷修改**：配置前预览并建立临时回滚点，配置后验证，失败恢复，不长期保留用户配置副本。
4. **不猜测成功，也不花钱买证明**：接入流程不发送计费测试消息（2026-09-13 决策），以配置写入回验与应用启动观察作为就绪依据，首次真实请求结果显示在「最近连接结果」中；没有完成写入回验时，不显示“已经可以使用”。
5. **服务端账单为准**：客户端价格和费用预测必须标为估算。
6. **秘密分权**：账号登录凭证与写入第三方工具的 API Key 是两种不同凭证。

## 5. 面向小白的一键式主流程

```text
启动野菜API
→ 点击“登录野菜账号”
→ 客户端申请一次性设备授权码，并由系统浏览器打开野菜API网站授权页
→ 网站未登录时，先完成网站现有登录
→ 授权页显示设备名称，用户确认授权官方桌面客户端
→ 客户端轮询授权结果并自动完成登录，显示余额与账号状态
→ 扫描已经安装的五类工具
→ 用户选择一个或多个工具
→ 客户端测试线路并给出推荐
→ 用户选择模型（真实模型 ID 始终可见）
→ 显示官网价与野菜实际价
→ 预览将修改的工具和文件
→ 创建加密临时回滚快照并写入配置
→ 读取回验（不发送计费测试消息）
→ 成功：删除快照，显示“已经可以使用”及启动提示
→ 失败：从快照恢复原配置，恢复完成后删除快照
```

目标浏览器授权采用第一方设备授权机制，需要以后增加 NewAPI 桌面授权接口。一次性设备码必须短期有效且只能使用一次；账号密码、网站 Cookie、API Key 和最终客户端会话不得出现在 URL 中。用户取消、拒绝、设备码过期或网络中断时，客户端必须显示真实状态并允许重新发起。用户可以在网站查看并撤销已授权设备，客户端下一次联网请求必须服从服务端撤销结果。当前客户端阶段只设计边界和接口占位，不伪造已经可用的浏览器授权。

授权时效固定为：一次性设备码有效 10 分钟；客户端访问令牌有效 1 小时并由长期设备会话自动刷新；本机连续 30 天未使用则会话过期，并且无论是否持续使用，最长 90 天必须重新完成一次网页授权。时效感知按客户端自治实现（2026-09-13 定案）：客户端本地记账授权时间与最近使用时间，超过 25 天提示「会话可能即将过期」、超过 80 天引导提前重新授权；本地记账不精确，提示不阻断主流程，不要求服务端改造。授权请求顺带附 `device_name`（本机主机名），服务端忽略无害、未来支持即在授权页展示设备名称。用户在客户端退出或在网站撤销设备后，本机长期会话立即失去续期资格，客户端下一次联网请求必须进入“已撤销”状态并清除本机账号凭证。长期离线导致会话无法刷新时，客户端要求重新登录，不用缓存余额或旧授权伪装为在线。充值、改密和其他敏感账号操作继续在第一方网站完成。

## 6. 信息架构与页面

### 6.1 首次使用 / 登录

- 产品价值说明。
- “登录野菜账号”主按钮。
- 浏览器授权进度、设备名称、取消、拒绝、超时和重新尝试。
- 明确说明：GitHub、LinuxDo 或密码属于网站登录方式，不是客户端内的不同账号类型。
- 授权成功前不发放客户端会话；成功后将设备范围的长期凭证放入系统安全存储。
- 退出账号时清除本机账号会话，但不擅自删除已经写入第三方工具的独立调用 Key。

### 6.2 首页

- 当前余额、今日/本月用量及数据更新时间。
- “配置我的 AI 工具”主操作。
- 已发现工具及健康状态。
- 当前线路概况。
- 余额不足、配置失效或模型下线提醒。
- 充值按钮（系统浏览器打开第一方 `/wallet`）。

### 6.3 工具中心

每个工具显示：

- 工具名称和图标。
- 已安装 / 未发现 / 版本不支持。
- 未配置 / 已配置 / 需要修复 / 外部变更冲突。
- 当前模型 ID、线路和上次验证时间。
- 配置、重新检测、诊断、查看最近操作结果。

“未发现”是普通空状态，不应显示为错误。V1 只提供安装说明，不执行安装。

### 6.4 一键配置向导

1. 选择工具。
2. 选择线路，默认给出测试后的推荐。
3. 选择模型。
4. 查看价格与兼容性。
5. 预览变更。
6. 创建临时回滚快照，执行写入与回验（不发送计费测试消息）。
7. 展示成功结果或恢复结果。

#### 6.4.1 已确认线路

| 展示名称 | 根地址 |
|---|---|
| 大陆优化 | `https://yeschoy.com` |
| Cloudflare 全球加速 | `https://api.yeschoy.com` |

根地址不等于每个工具最终写入的完整 Base URL。Claude Code、Codex、Pi 和 DSH 的协议路径规则分别由对应适配器负责，OpenCode（即将支持）的路径规则随其适配器排期补充；高级详情必须展示最终将写入的有效地址。

两条线路共用同一野菜账号、API Key、模型可用性和计费价格，只改变网络路径。客户端可以测试后给出推荐，但更改已经配置的线路必须经过用户确认和正常的配置事务，不允许后台静默改写。

### 6.5 模型与价格

模型卡片至少展示：

- 真实、可复制的模型 ID。
- 厂商和用途标签。
- 兼容的工具与协议。
- 推荐、最快、最强、经济等解释性标签。
- 可用、维护、下线或分组不可用状态。
- 官网输入、输出、缓存价格。
- 当前用户的野菜实际输入、输出、缓存价格。
- 阶梯价、高峰/低峰价、长上下文价或固定请求价。
- 官网来源链接、最近核对时间和本站价格版本。
- 输入和输出分别计算的节省比例；不可同口径比较时不显示折扣。

默认列表只展示当前账号实际可用、且兼容当前所选工具的模型。用户可以切换到“查看全部模型”；不可用或不兼容的模型保持可见但置灰，并明确说明原因。已经选择的模型后来下线或失去权限时，客户端要求用户重新选择，不得静默替换成另一个模型。

模型事实采用单一权威分工：当前账号可用性、真实模型 ID、官网基准价格数值和野菜实际价格均以 NewAPI 实时数据为准，客户端不得再维护一套独立的价格数值。工具兼容性、推荐标签、中文说明，以及 NewAPI 暂未提供的官网来源 URL、核对时间等说明性元数据，由野菜API维护的版本化模型目录补充；暂不修改 NewAPI 时，该目录随签名客户端发布，以后再由版本化服务端接口下发。服务端出现尚未收录的新模型时可以展示真实 ID 和 NewAPI 返回的价格，但不得猜测兼容性、价格来源或折扣。

价格比较以“人民币 / 100万 tokens”为主显示，同时保留官网原始币种和原价。V1 初始固定汇率为 `1 USD = 6.75 CNY`，不自动跟随短期市场波动；界面显示汇率值、版本和生效日期，由产品负责人在汇率波动较大时发布新版本。该固定汇率只用于价格比较，不参与实际扣费，也不追溯修改历史账单或历史估算。输入、输出、缓存读取、缓存写入、长上下文阶梯和高峰/低峰分别展示；图片、音频、按次计费保留其原生单位。依据过期或无法同口径比较时，不展示节省比例或统一折扣结论。

可选成本计算器：用户输入预计输入量与输出量，客户端给出官网预计费用、野菜预计费用和预计节省金额。结果必须标记为估算。

当前 NewAPI `GET /api/pricing` 已观察到模型、基础倍率、输出/缓存倍率、分组倍率、计费表达式和价格版本。现有前端对 token 计费模型按“基础倍率 × 2 × 展示分组倍率”计算输入价格，再应用输出和缓存倍率；因此同一份 NewAPI 数据可以给出基准价格与用户分组后的价格，不需要客户端复制一份官网价格表。[NewAPI 价格接口](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/controller/pricing.go)、[价格计算](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/web/src/features/pricing/lib/price.ts)、[分组倍率](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/web/src/features/pricing/lib/model-helpers.ts)

V1 口径：客户端直接比较 NewAPI 的官网基准价格与应用当前用户、分组和特殊计费规则后的野菜实际价格。客户端随包目录只补兼容性、说明和价格来源元数据，不保存另一份价格数值。产品已确认一项长期硬规则：NewAPI 的 `model_ratio`、`model_price` 或基础 `billing_expr` 始终维护为对应厂商官网价格；野菜折扣只能通过用户分组倍率或明确分离的特殊计费规则叠加。因此客户端可以把基础价格标为“官网价”。阶梯计费、按次计费和特殊表达式必须复用 NewAPI 的完整计费语义，不能套用简化倍率公式。[价格结构](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/model/pricing.go)、[倍率同步](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/controller/ratio_sync.go)

价格维护必须遵守以下约束：自动同步得到的 OpenRouter、models.dev 或其他渠道价格不得未经官网核对就覆盖官网基准价格；厂商调整官网价格时，NewAPI 的基础价格、价格版本和客户端补充的来源元数据应作为同一次运营变更发布；任何野菜促销、用户折扣或渠道优惠不得写回官网基准字段。

### 6.6 余额与用量

- 余额、累计使用、请求次数。
- 今日、本月及自定义日期用量。
- 按工具、API Key、模型和线路聚合。
- 明细至少包含时间、工具、模型、输入/输出/缓存用量、计费金额和结果。
- 数据过期、部分加载和接口错误必须显式显示。

现有 NewAPI 路由已经声明用户资料、模型、充值、价格和会话相关能力；客户端接入前仍需以实际部署版本做契约验证。[NewAPI API 路由](https://github.com/QuantumNous/new-api/blob/ac381acf4bf41204b97bb26b4c58c83275877a2e/router/api-router.go)

### 6.7 诊断与修复

诊断按层级执行，不能只返回“连接失败”：

1. 工具是否存在、版本是否受支持。
2. 配置文件是否存在、可读、格式有效。
3. 当前野菜配置是否与客户端记录一致。
4. DNS、TLS、代理和基础网络是否可达。
5. API Key 是否有效。
6. 余额是否足够。
7. 模型是否可见、支持该工具所需协议。
8. 发送最小协议请求并识别上游错误。

诊断不得上传用户提示词、项目文件内容或完整密钥。任何会修改文件的“修复”都必须先预览并建立加密临时回滚快照。

### 6.8 设置与高级模式

普通模式只展示业务语言。高级模式可查看但不强迫用户编辑：

- 实际 Base URL。
- 密钥存放说明与撤销入口（恢复原设置即撤销）。密钥掩码与创建时间属服务端数据，V1 按客户端自治原则不要求服务端改造，以指引文案替代（2026-09-13 定案）。
- 配置文件位置。
- 实际模型 ID 与协议。
- 最近一次配置操作的结果；不提供历史备份列表。
- 客户端版本、更新通道和诊断日志导出。

## 7. 五类工具适配原则

| 工具 | V1 配置方向 | 关键要求 |
|---|---|---|
| Claude Code | `~/.claude/settings.json` 中的 Anthropic Base URL 与认证变量 | Base URL 不多加 `/v1`；保留用户其他设置 |
| Codex | `~/.codex/config.toml`、认证存储及模型目录 | 使用 Responses 协议；保护用户官方登录状态；必要时提示重启 |
| OpenCode（即将支持，V1 不实现适配器） | `~/.config/opencode/opencode.json` 的 provider 节点与固定签名认证插件项 | 只合并野菜 provider；认证 loader 运行时调用凭据助手；不向普通配置或 `auth.json` 写完整 Key |
| Pi | `~/.pi/agent/models.json` 的显式 provider 与可选默认模型 | `apiKey` 只写原生 `!command`；不接管 Pi `auth.json`；处理目录覆盖与并发变更 |
| DSH | `web` profile 的`$DSH_HOME/settings.yaml`、profile patch与独立凭据provider | 仅`web`自动配置；其他profile零写入发现；密钥不写进settings.yaml、`.credentials.yaml`或`.env`；精确版本通过完整矩阵后按正常V1支持展示，不加Developer Preview产品标签 |

V1 已确认采用精确版本兼容白名单：只有在 Windows/macOS 完整矩阵中通过配置、凭据、真实请求、冲突恢复、移除和秘密扫描的精确版本才能一键配置。新发布、更高、未知、失败或未验证版本只读发现，不依据“最低版本以上”或开放语义版本范围推断兼容。

DSH 是正常 V1 支持目标，但不作为整体发布阻断项。若发布时没有精确 DSH `web` 版本通过矩阵，客户端只显示“已检测到，当前版本暂未支持自动配置”，不创建 Key、不安装插件、不写配置；产品页和发布说明只列出真实已验证工具，后续通过签名客户端更新增加 DSH 正常支持。

CC Switch 已观察到 Pi 适配、原子写入和私有文件写入能力，可作为实现证据基础，而不是对野菜API已经兼容的证明。[CC Switch 配置写入](https://github.com/farion1231/cc-switch/blob/3217f72596f2d1c0f879f0a05f83803825d9809f/src-tauri/src/config.rs)、[Pi 适配](https://github.com/farion1231/cc-switch/blob/3217f72596f2d1c0f879f0a05f83803825d9809f/src-tauri/src/pi_config/mod.rs)

## 8. 本地配置事务与临时回滚

每次配置动作是一个完整事务：

```text
扫描目标文件及版本
→ 记录文件身份、权限、内容哈希
→ 生成拟写入结果
→ 展示变更摘要
→ 创建加密的临时回滚快照
→ 再检查目标是否被外部修改
→ 原子写入
→ 重新读取和语法验证
→ 读取回验（不发送计费测试消息）
→ 成功提交并删除快照；失败从快照恢复，恢复完成后删除快照
```

必须处理：

- 文件不存在。
- 配置格式已损坏。
- 同一工具存在多套配置目录。
- Windows 与 WSL 配置并存。
- 用户在向导期间从外部修改文件。
- 工具运行中锁定文件。
- 应用异常退出或设备断电，下一次启动检测未完成事务并从临时快照恢复。
- 恢复失败时不得删除快照，需要保留人工恢复路径和操作编号，直至恢复完成或用户明确放弃。

V1 不提供长期历史备份或任意时间点恢复。临时快照只服务于当前未完成的配置事务，不上传云端，不支持跨设备迁移；系统安全存储不可用时，客户端不得退化为明文快照，而是拒绝修改配置。

## 9. 安全边界

### 9.1 两种凭证

1. **野菜账号会话**：查询账户、余额、用量和管理授权。
2. **工具调用 Key**：写入 Claude Code、Codex 等工具配置，用于模型请求。

桌面账号会话采用最小权限。它只允许读取当前账号的基础资料、余额、用量、可用模型和价格，并创建、复用、轮换或撤销“当前设备 × 当前工具”的调用 Key，以及退出当前设备。它不得修改密码、邮箱、支付资料、充值记录、用户分组、其他设备、其他设备的工具 Key 或任何后台管理设置，也不得读取其他设备 Key 的完整明文。充值、改密、设备总览和其他敏感账号操作统一打开第一方官网完成。

账号会话不得写入任何第三方工具配置。工具调用 Key 固定采用“账号 × 设备 × 工具”粒度：同一账号在同一台设备上的 Claude Code、Codex、OpenCode、Pi 和 DSH 分别使用独立 Key；切换线路或模型继续复用该工具 Key，重复执行配置必须幂等返回或复用同一个 Key，不得不断创建新 Key。另一台设备必须获得另一组 Key。这样可以按设备和工具归因用量、单独撤销并限制泄露影响范围；这需要以后增加幂等发 Key 接口。

客户端重装后如果无法安全证明仍是原设备身份，则按新设备处理并创建新一组工具 Key；旧 Key 不因重装或重新登录而自动失效，保留至用户明确撤销，避免误伤仍在运行的工具实例。

撤销与轮换采用三类明确语义：

- **退出账号**：只清除客户端账号会话，不撤销或删除已经写入第三方工具的独立调用 Key。
- **撤销设备**：用于设备遗失、被盗或不再受信任的场景，同时撤销该设备的账号会话和全部工具 Key；客户端下次联网必须显示已撤销。
- **轮换单个工具 Key**：先创建替代 Key，建立临时回滚快照并写入目标工具，完成读取回验后才撤销旧 Key（不发送计费测试消息）；任何写入或验证失败都保留旧 Key 并恢复原配置。

用户只删除某个工具的本地配置时，客户端必须单独询问是否同时撤销该工具 Key，不得把删除配置与远程撤销默认为同一动作。

### 9.2 凭证存储

- 账号长期凭证进入 macOS Keychain 或 Windows 系统凭据存储。
- 内存中的短期令牌到期后清除。
- 工具 Key 只写入工具确实要求的存储位置。
- 不在日志、崩溃报告、剪贴板历史或诊断包中保留明文密钥。
- 远程网页授权窗口不得获得 Tauri 特权 IPC。

### 9.3 临时回滚快照

- 只在一次配置事务期间创建，不形成历史备份列表。
- 快照整体加密，随机解密密钥存放在 macOS Keychain 或 Windows 凭据管理器，并限制文件权限。
- 配置验证成功后立即删除；失败时恢复原配置，恢复完成后立即删除。
- 应用崩溃或断电后，下一次启动优先恢复未完成事务；恢复失败前不得删除快照。
- 不上传云端、不支持跨设备恢复，且用户界面不得展示其中的完整密钥。
- 系统安全存储不可用时拒绝修改配置，不得写入明文快照。

### 9.4 自动更新

- 更新清单和安装包都必须验证签名。
- 只接受固定的第一方更新来源。
- 下载失败或签名失败不得替换现有版本。
- 保留上一可用版本和失败恢复路径。
- 发布前需要 Apple Developer ID、公证配置和 Windows 代码签名证书。

### 9.5 基础运行遥测与崩溃发现

V1 使用野菜API自建的第一方基础运行遥测，默认开启，用于尽早发现真实故障。首次启动必须在任何遥测上传前，以明显、易懂的方式告知采集目的、字段类型、接收方和保存期限，并提供可见的关闭入口；用户关闭后不影响登录、余额查询、工具配置或模型调用，并立即停止后续遥测上传及删除本地待上传队列。不得引入会自行扩展采集范围的第三方统计 SDK。

自动上传采用字段白名单，仅允许：

- 客户端版本、构建号和更新通道。
- 操作系统版本与 CPU 架构。
- 工具名称、工具版本和适配器版本。
- 操作类型、执行阶段、成功/失败、匿名错误码和耗时。
- 线路类别和真实模型 ID。
- 去除用户名、完整路径、参数值和用户数据后的崩溃指纹与应用代码栈。
- 与账号 ID、设备授权 ID 和 API Key 分离并定期轮换的随机遥测 ID。

以下内容永远不得自动上传：API Key、账号凭证、完整配置文件、提示词、模型回复、项目代码、项目文件内容、完整本地路径、操作系统用户名、剪贴板内容和原始内存崩溃转储。用户尚未看到首次告知前发生的崩溃只能保存在本地。需要原始诊断材料时，必须由用户主动发起、先展示摘要并完成脱敏后一次性发送。

保存期限固定为：普通运行事件保留 30 天；脱敏崩溃事件与代码栈保留 90 天；完全去标识且无法还原到单台设备的汇总趋势保留 12 个月；随机遥测 ID 每 30 天轮换；本地待上传队列最多保留 7 天，超期事件直接丢弃。用户关闭遥测时立即删除本地队列，并可以同时发起历史原始事件删除请求；已经完成不可逆匿名化的汇总统计不受该请求影响。重大安全事件需要延长保存时，必须记录范围、原因、批准人和删除日期，不得无期限保存。

- Rust 侧适合执行受控文件写入、权限处理、进程检测和原子恢复。

- 保留 CC Switch 的 MIT 许可证和原版权声明，并单独审计其依赖许可证；“可 fork”不等于所有依赖都自动获得同一许可结论。
- 复用代码必须经过野菜API安全边界和五类工具版本契约验证，不能因为上游存在某个适配器就宣称已经支持。

- 野菜API自己的账号、计费、设备授权、工具 Key、价格对比和遥测代码保持清晰模块边界，避免未来跟随上游升级时产生不可控耦合。

## 11. 与 CC Switch 的差异化

| 维度 | CC Switch | 野菜API V1 |
|---|---|---|
| 产品身份 | 通用多服务商配置和切换工具 | 野菜API官方客户端 |
| 用户 | 熟悉 Provider、Key、模型和配置的用户 | 不理解 API 配置的普通用户 |
| 账号 | 以本地 Provider 管理为中心 | 野菜账号、余额、充值、用量为中心 |
| 配置 | 用户主动新增和切换 Provider | 扫描工具、推荐线路/模型、一键配置 |
| 模型 | 以配置和映射为中心 | 真实模型 ID、兼容性、推荐与价格比较 |
| 价格 | 非主要交易入口 | 官网价格与用户实际价格同口径比较 |
| 故障处理 | 面向技术配置排查 | 分层诊断、解释原因、安全修复和恢复 |
| 服务商范围 | 多服务商 | V1 只对野菜API负责，不做通用服务商市场 |

差异化不是减少功能，而是改变主任务：CC Switch 帮用户“管理配置”，野菜API帮助用户“从账号直接变成可用工具”。

## 13. 关键页面状态

每个主要页面都必须覆盖：

| 状态 | 用户可见事实 | 允许动作 |

| 恢复中 | 正在从临时快照恢复，不能宣称完成 | 等待、查看操作编号 |
| 处理中 | 正在建立回滚点、写入或验证 | 取消仅在安全边界允许时出现 |
