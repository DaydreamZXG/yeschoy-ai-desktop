# 野菜API：费用对比客户端验证记录

日期：2026-08-31。实施范围：RU-015，客户端费用明细校验及展示。不是完整产品验收，也不是实际账单接通证明。

## 已实现

- 用量账单增加「官网同用量估算 / 野菜实际扣费 / 预计节省」；缺少真实账单时显示横线及未接通说明。
- 输入、输出、缓存读、5 分钟/1 小时缓存写逐项核算，验证输入包含缓存时不得重复计算。
- 官网分项金额用整数微单位计算，每项四舍五入至原币小数点后 6 位。美元按固定 6.75 逐笔换算至人民币 6 位后汇总；人民币不换算。已结算的本站净扣费不乘汇率、不重新定价。
- 两边仅汇总同一可比请求集合，单列未纳入的已知扣费、未结算记录及原因。缺少价格历史、完整用量、可靠模型映射或支持的计费方式时，不补零、不虚构节省。
- 负差额显示「高于官网估算」，零差额显示持平；微小非零金额显示 `<¥0.01`，避免显示成免费。官网总额小于一分时不展示比例。
- 可展开查看完整模型 ID、记录编号、使用时间、官网模型、适用条件、价格版本、生效和核对时间、来源、汇率、各项数量及单价。规则说明公开舍入方式与百分比公式。
- 检查账号/统计范围、有效期、重复记录、金额一致性和未知字段。过期或切换账号后清除金额，不保留旧账单冒充当前数据。
- 支持简体中文、繁体中文、英文、日文，沿用现有浅色/深色样式和字体。

## 当前没有接通的能力

正式入口 `AccountView` 没有传入任何账单，也没有新增网络请求、登录方式、密钥读取、配置写入、遥测或更新。

`comparison.ts` 中的数据结构是**本地显示核验输入**，不是已部署的服务端 API，也不构成身份认证或模型真实性证明。即使数学一致，客户端仍无法单独证明上游模型、价格档位、资金来源、退款和用量来源真实。

2026-08-31 以匿名 GET 只读检查以下入口，两个均返回 HTTP 404 JSON：

- `https://yeschoy.com/api/desktop/v1/bootstrap`
- `https://api.yeschoy.com/api/desktop/v1/bootstrap`

未修改任何服务器、NewAPI、Nginx 或线上配置。本次没有调用模型。

## 给后端技术负责人的接入清单

继续沿用已有桌面接口交接方案，先实现第一方授权及桌面 bootstrap；不要用浏览器会话、管理员令牌或直接读取网站凭据代替桌面授权。

费用对比生产者还必须提供并验证：

1. 当前授权账号、统计范围及结算截止时间；稳定的原请求标识，能将重试、退款、冲正关联到原账单，不使用展示行号去重。
2. 同一完整请求集合的标准化用量及净结算金额；未纳入的记录及原因也要齐全。分页必须有稳定快照及完整性检查。本地结构最多接收 1000 笔，不得把截断后的首页冒充整月全量，也不得仅挑选优惠记录。
3. 从 NewAPI 维护的官网基准取得**当时**生效的价格快照、版本和来源，映射到真实模型及服务条件；不能将今天的价格直接用于旧请求。
4. 分开给出普通输入、输出和各种缓存。处理协议的输入是否包含缓存、推理 token 是否已含在输出中，防止重复计费。长上下文、阶梯价、服务档位、批处理等由后端判定，客户端不复制表达式引擎。
5. 本轮仅接收完整的按 token、钱包净结算记录。媒体、按次、套餐、赠送/混合资金及其他未定义的收费方式，先明确排除，后续经独立核算规则验收再开放。
6. 服务端计算规则与本轮整数/舍入约定一致；不一致时版本化升级，不能通过更换金额字段绕过校验。官网金额是同条件估算，不冒充厂商实际发票，余额扣减不冒充充值现金支出。
7. 通过已认证的通道提供当前有效数据并支持刷新，绑定账号/范围，拒绝过期缓存。客户端校验不能替代服务端授权、账本及价格来源校验。

这些是后续接口合作事项，不代表本轮已冻结或实现了后端接口。测试样例均为虚构算式，不能导入为生产价格表。

## 验证与限制

- 已通过 TypeScript 检查、前端生产构建。
- 新增核算和界面测试、已有工作台及七组接入回归测试均执行；精确结果以 RU-015 执行报告和本轮终端结果为准。
- 浏览器检查了实际无账单状态的浅色/深色页面和可展开计算说明；1280 像素宽度下没有横向溢出。真实带账单页面目前仅有组件测试，不宣称线上联调或全部窗口尺寸视觉验收完成。
- 生产入口没有导入 `src/billing/test-fixtures.ts`；测试数值只供测试，不作真实模型价格或真实账单展示。
- 直接使用继承的 Vitest 默认扫描曾跟随旧 DMG 的 Applications 符号链接进入 Xcode，发生路径过长错误。验证命令显式排除 `release/**` 和 `work/**`，没有删除旧产物或修改无关配置。
- 构建有既有的浏览器兼容数据库过期及大包警告。本轮没有升级依赖或改变发布设置。
- 本轮未实现 DSH 受控启动/密钥配置，也未构建新安装包、签名、公证或推送 GitHub。

## DSH 后续阻塞项

本机发现 DSH `0.1.0-rc.6`，但版本发现不等于接入验证。只传 `--host 127.0.0.1 --port 0` 无法保证现有配置不会覆盖监听或权限，启动还可能恢复已有自动任务。

在实现托管启动前，需确定并验证工作目录、环境隔离、配置覆盖规则、浏览器本机地址来源、进程退出策略、凭据传递及既有自动任务的行为。不能静默更改用户的 DSH 全局配置，也不能把浏览器打开成功标成野菜API连接成功。当前未启动 DSH、未读取其用户密钥、未修改其设置。
