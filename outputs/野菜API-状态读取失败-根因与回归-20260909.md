## 已确认的缺陷

1. `src-tauri/src/tool_adapters/codex_desktop.rs` 的 `Prepared::validate_readback` 使用 `document["model_providers"]["yeschoy"]`、`provider["experimental_bearer_token"]` 等索引读取外部配置。锁定依赖 `toml_edit 0.24.1+spec-1.1.0` 在键不存在时会 panic，并不会像 `serde_json::Value` 一样返回空值。
2. 旧版 helper/gateway 配置可能有 `auth.command`，而没有直连方案所需的 `experimental_bearer_token`。检查旧记录、迁移网关配置或发现外部修改后，现有检查链路会进入这个只读验证器。缺失字段原本应判定为设置需要更新，却导致 worker 异常退出。
3. `tool_activation.rs` 的接入状态检查在同一个任务中收集七个应用。单个应用 panic 原本会丢弃整批结果，并由 worker 边界返回 `connection_inspection_failed`，从而让 Claude 等其他应用也显示未知状态。

Windows 修复前回归直接报告：

```text
src/tool_adapters/codex_desktop.rs:395:25:
index not found
test result: FAILED. 0 passed; 1 failed
```

## 本轮代码修改

- 对所有 Codex 读回必需字段改用 `get` 和类型检查。字段缺失、类型错误、配置为空、文件缺失以及旧版认证结构均正常返回 `configuration_readback_failed`，由既有状态逻辑保留为需要调整的配置，不崩溃、不覆盖文件。
- 批量检查按应用隔离异常：仅失败的应用返回 `unavailable`，保留其余六个结果。响应中不包含原始 panic 文本、密钥或文件路径，既有日志继续按请求编号、工具 ID 和封闭原因码关联。
- 部分失败提示不再无依据地归因于系统凭据访问；仍提供重试和诊断编号。
- 增加实际配置文件读回回归、worker 边界回归、异常隔离回归及前端部分结果回归。没有另建供应商数据库、网关或缓存。
