## 0. 先读这一节：本轮代码一行都没有编译过

工作是在一台 **Linux 服务器**上做的（`/opt/yeschoy-download` 那台），不是开发用的 Mac。那台机器上：

- **没有任何 Rust 工具链**（`cargo`、`rustc` 都没有）
- **没有 `node_modules`**，也没有 `pnpm`

所以本轮所有改动：**没有编译过，没有跑过一个测试**。这是接手时最大的风险，不要按"已验收"对待。

实际做到的静态验证，逐项列出，免得高估也免得低估：

## 1. 本轮改了什么

五轮工作，按问题来源分组。

### 1.1 登录登不上 / 上下文不压缩（起点问题）

**登录**的根因不是某一个 bug，是**所有失败路径塌缩成同一个静默转圈**，一直转到 10 分钟设备码过期，真正原因从不显示。

- `account_v2.rs` 原本**零日志**。补了分阶段日志：bootstrap 13 条契约判断改成具名 `rejection` 链（`envelope`/`schema_version`/`service`/`contract_id`/`client_too_old`/`capabilities`/`fx_rate`/`paths`/`wallet_url`），账户投影不可用、会话载荷长度（诊断 Windows 凭据 2560 字节上限）都会落日志。
- 新增 `InstallFailure { Contract, Storage }`，把"服务端返回不合契约"和"密钥写不进系统钥匙串"分开 —— 之前两者都报同一个错。
- `parse_account` 的计数器改成非阻断：`used_quota` / `request_count` 畸形（负数、`null`、字符串）不再拒绝整个账户，只有余额仍是必需。**这是作者明确拍板的**：负数计数器不该让人登不上。
- `useAccountSession.ts` 加了 `TRANSIENT_TOLERANCE = 3`：连续 3 次以内的瞬时失败保留旧投影，超过就如实显示，不再无限静默转圈。

**上下文不压缩**的根因是 `parse_context_overflow` 只匹配 OpenAI 那一种英文措辞，别的上游溢出原样透传，Claude Code 认不出来，于是永远不触发压缩。

- `claude_bridge.rs` 加了宽口径 `is_context_overflow`（含中文措辞），认不出具体数字也会转成 Claude Code 能识别的 `invalid_request_error`。
- `[1m]` 不可用时的拒绝从 `api_error` 改成 `invalid_request_error` —— 前者会被 Claude Code 当成上游故障。
- beta 头只对 Anthropic 原生模型下发（`tool_model_profile::is_native_claude`）。
- 新增遥测 `one_m_declared_above_relay relay_maximum=`：**中转实际不给 1M 的模型会被记下来**，用来决定哪些模型该停止声明 1M。

### 1.2 界面（作者原话："很密集很难看"）

- **主色**：`#c93e22` → 深松绿 `#1c6b4a`（深色 `#5cc08d`）。原来的 accent 跟 `--danger #b3413d` 几乎同色，每个主按钮都像在报警，健康余额显示在粉色卡里像出错。红色现在只留给真正的危险。
- **字号阶梯**：新增八级 token，12px 下限。318 处 `font-size` 重写；原来 17 种字号（9–29px）压到 8 级。114 处 ≤11px 全部提到 12px。

## 2. 最重要的一条：环境变量读错了进程

`claude_code.rs` 那个守卫的名字本身就说明作者知道优先级关系：

```rust
fn higher_precedence_override() -> bool {
    [...].any(|key| std::env::var_os(key).is_some_and(...))
}
```

读的是 **GUI 进程自己的环境**。macOS 上从 Dock 启动的 app 继承 launchd 的环境，**不 source `.zshrc` / `.zprofile`**。而 `terminal_launch.rs` 用 `open -b com.apple.Terminal` 把命令交给 Terminal，Terminal 跑的是**登录 shell**，会完整加载 rc。

后果链条：

1. 用户从别家中转站过来，`.zshrc` 里有 `export ANTHROPIC_BASE_URL=...`
2. 守卫看不见 → 放行 → 写 `settings.json` → readback 校验文件内容通过 → **界面显示"接入成功"**
3. 助手开 Terminal → 登录 shell 设上变量 → **流量还是走旧中转站，钱扣在别人那边**

这个守卫本来就是为了防这件事写的。而且方向是反的：开发时从终端 `pnpm tauri dev` 启动，守卫**能**看见 —— 所以**这个 bug 在开发机上几乎撞不见**。

同根因另外三处：`codex_desktop.rs` 的 `CODEX_HOME`、`dsh_web.rs` 的 `DSH_HOME`、`pi.rs` 的 `PI_CODING_AGENT_DIR`。

**修法**：新模块 `src-tauri/src/shell_environment.rs`，启动时跑一次 `$SHELL -lic`，哨兵包裹 + 固定 key 清单（横幅、MOTD、值含 `=` 都不会污染解析），忽略退出码（交互式 rc 最后一条命令失败太常见）。两个访问器语义不同，是刻意的：

- `var_os(key)` —— 路径解析用。登录 shell 说了算；它明确没设就是没设，不回退本进程的值。
- `is_set_anywhere(key)` —— 拒绝式守卫用。**两边任一有值就报**。多提醒一次只花一条消息；漏掉一次，钱扣在别人那边。

`initialize()` 在 setup 里和两个 resume **并发**执行，不是在它们之前 —— 串行会让登录 shell 启动多久、回环桥就晚起多久。冷启动没解析完时回退 `std::env`，也就是今天的行为：**热了严格更好，冷了绝不更差。**

`externalOverride` 文案重写了。这条以前几乎不出现，现在会**真的**弹给那批从别家迁过来的用户 —— 而他们最可能不知道什么是环境变量。改成了能照着做的步骤。

**同根因还导致"检测不到已装的应用"**：`tool_discovery.rs` 用同一个残缺 `PATH` 扫可执行文件，兜底目录漏掉 **nvm**（macOS 上最常见的 Node 装法）。补了 nvm / fnm（mac 和 Linux 路径不同）/ volta / bun / asdf / yarn；Windows 补了 Volta / bun / scoop / fnm / Yarn。版本化目录用 `versioned_directories()` 展开，每个管理器上限 12 个。

## 3. 多台电脑会互相踢掉（作者提问查出来的）

**登录本身没问题**，设备码流程本来就是多设备设计的，客户端还会发 `device_name` 给授权页显示，没有任何单设备限制。服务端有没有限制这个仓库看不出来，**请去后台确认**。

**但接入的密钥管理是单机独占假设。** token 名字形如 `野菜API cc-<分组哈希>-<16位随机>`，**名字里没有设备标识**。`find_token_id` 按前缀搜，把搜到的所有同前缀同分组 token 都当成自己的，没被复用的全部进 `retire_after_commit`，接入提交后发 `DELETE /api/token/{id}`。

而复用条件 `reusable_token()` 要求**模型集合完全相等**。于是：

| 场景 | 结果 |
|---|---|
| 不同分组 | 前缀不同，互不相干 ✅ |
| 同分组，模型集合完全一致 | B 复用 A 的 token，两台都能用 ⚠️ 共用一把钥匙 |
| 同分组，模型集合有任何差别 | **B 新建并删掉 A 的 → A 那台直接失效，无提示** ❌ |

用户在第二台机器上多勾一个常用模型就会触发。

**修法（方案 A）**：16 位后缀劈成「设备 8 位 + 随机 8 位」。**长度和字符集都没变**，所以已装的旧客户端照样能解析新名字。前缀扫描加 `token_is_ours` 过滤，复用和 retire 都只在本设备的 token 里发生。

设备 ID 在 `~/.yeschoy/device-id`，**刻意不放钥匙串** —— 丢了等于这台机器的钥匙全变孤儿，而钥匙串恰好是已知会消失的那个存储。

**升级代价，必须告诉用户**：升级前建的 key 是随机 16 位，**跟别台电脑的 key 分不出来**，所以既不复用也不删除，每台机器每个（工具 × 分组）留一个孤儿 key。这是刻意的 —— 猜错方向就是回到正在修的 bug。**发版说明里请提示用户去后台清一次旧 key。**

## 4. 其余适配器问题

**WorkBuddy 是唯一把真实计费密钥明文落盘的**（`~/.workbuddy/models.json`，`route.upstream_key()`，直连远端）。其余五个都走 helper 命令 / 环境变量 / 回环 token。WorkBuddy 的配置格式不支持 helper，没得选。做了两件事：

- 写入前 `narrow_third_party_file()`（chmod 0600）。`atomic_write` 会把目标 mode 复制到替换文件，所以先收紧能覆盖新内容。
- `readyWorkBuddy` 文案加一句告诉用户这个应用不一样，别放网盘同步目录。

**刻意不对它设 Windows DACL**：那是别人应用的文件，protected DACL 会剥掉继承的 SYSTEM / Administrators，可能撞上备份或终端防护 agent；而被剥掉的那些账户本来就能读整个用户目录，几乎买不到什么。真正的威胁是同机别的用户账号（用户目录 ACL 已覆盖）和网盘同步（ACL 管不了，只能靠告诉用户）。

**钥匙串丢了 = 原配置永久回不来**。`connection_recovery.rs` 的日志用 AES 加密，**密钥在系统钥匙串**。钥匙串条目没了（重置登录钥匙串、换开机密码、清 Windows 凭据管理器），`.sealed` 解不开，而**原始配置只存在于那个日志里** —— 磁盘上的 config 已经是被改过的版本。

修法：`save()` 额外落一份 break-glass 明文副本到 `~/.yeschoy/connection-recovery/original/<tool>/`，含 `manifest.json` 和中文《如何手动恢复.txt》（UTF-8 BOM + CRLF，因为会打开它的人大概率在 Windows 上用记事本，而且已经出事了）。

**fail-closed**：目录 0700、文件 0600；Windows 走 `mod windows_acl`（`windows-sys` 裸 FFI，SDDL `D:P(A;OICI;FA;;;<SID>)`，`P` 是承重位）。**任何一步失败就 `remove_dir_all` 整个目录再返回** —— 这段 FFI 在服务器上完全无法验证，fail-closed 保证它就算是错的，最坏也只是回到没有副本的状态，而不是漏一份。

**其他**：
- `FileTransaction::commit` 的两处 `?` 会留下半改状态（已修，上一轮）。`rollback_written` 遇到被外部改过的文件会就地 `return`，**后面的文件不回滚了** —— Claude Desktop 写 4 个文件，Pi 写 2 个。改成跑到底并报告最严重的那件事。
- `ui-switch` 轨道 44×24 / 滑块 20 / 行程 20，三个数字互相咬合。
- 单选框 `flex: 0 0 18px` 配 `width: 16px`、应用卡 header `38px` 轨道装 `40px` 图标，两处真实错位修掉。

**安装位置选择**：查出来一件事 —— **选哪个安装什么都不影响，除了启动谁**。六个适配器的 `prepare_catalog` 全都只接收 `home`，配置写在用户目录，选哪个副本写出来的文件一模一样。所以那个下拉框问的是"启动哪一个"，文案却写"选择要使用的安装位置"，**用户答的是另一个问题**。

对 CLI 更有害：终端里敲 `claude` 跑哪个由登录 shell 的 PATH 定死。让用户挑第二个，就是"打开终端使用"启动 A、他自己的终端跑 B。

改成：`asks_which_installation()` 只对桌面应用返回 true；CLI 取 PATH 序第一个可用的。标签从"安装 1 · 系统 PATH"（CLI 的 version 是空的，两项完全看不出区别）改成带 `~` 缩写路径 —— 去掉账号名，区分度不减。**不透明 id 保护的是入站方向**（渲染层回传 id 不是路径，没法指挥后端碰任意文件），出站放个给人看的标签不削弱这一点。

## 5. 侧边栏与公告

侧边栏原来只有三项。改成：我的应用 / **应用接入**（新增，用的是 `copy.ts` 里早就定义、从没用过的 `apps` 键）/ 用量账单 / **公告**（服务端宣告了才出现）/ 设置，底部加 **加入交流群**（从首页页脚提上来，对一个靠 QQ 群做客服的产品，用户最需要它的时刻是哪里都点不通的时候）。

**连接诊断和已安装的工具留在设置里**：前者是出问题时客服让你点的检查，后者跟"我的应用"内容基本重复，多出来的只有版本号。都不是顶级目的地。

交流群对话框状态提到了 `App.tsx`（`CommunityGroupDialog`）—— 侧边栏和页脚都要能开它，两份 `useState` 会变成两个互不知情的对话框。

### `deny_unknown_fields` 的坑（做公告时撞到的）

`BootstrapData` 上挂着 `#[serde(deny_unknown_fields)]`，意味着**服务端加任何一个字段，所有已装客户端立刻登不上**。同文件里 `DataEnvelope` / `DeviceAuthorization` / `AuthBundle` 全是宽松的 —— bootstrap 这两个是异类，不是规矩。已改成宽松。严格该留在渲染层输入（`AccountRequest`）和本地记录（`StoredSession`）上。

**这个不管做不做公告都该修。**

## 6. 服务端待办

### 6.1 公告接口

bootstrap 增加**可选**字段 `announcements_path`，形如 `/api/desktop/v2/notices`：

```
GET {origin}{announcements_path}      Authorization: 会话令牌
{"success":true,"data":{"notices":[
  {"id":"...","title":"...","body":"...",
   "severity":"info"|"warning","publishedAtEpochMs":1758000000000}]}}
```

客户端侧约束（已实现）：

- `announcements_path` 必须是**同源相对路径**，绝对 URL 一律丢弃 —— 这个值决定客户端带着令牌去哪里取数据。丢弃不是拒绝：一个格式错的可选字段不该让用户登不上。
- 正文当**不可信自由文本**，后端前端各过滤一遍控制字符和 bidi 覆盖字符；限长标题 120 / 正文 2000 / 最多 30 条；**只按换行分段，绝不当标记解析**。
- 服务端没宣告 → `available: false` → 侧边栏不显示入口。**客户端和服务端谁先发布都不会出错。**

### 6.2 token 设备隔离要确认的

- `/api/token/search` 的 `keyword` 是不是前缀匹配
- 后台对单账户 token 数量有没有硬上限（方案 A 会让每台机器各有一把 key）
