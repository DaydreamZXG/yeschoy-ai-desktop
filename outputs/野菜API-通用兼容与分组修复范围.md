# 通用兼容与计费分组修复

本次依据：2026-09-03 用户明确要求修复版本误拦截、计费分组缺失，以及展示价格与实际使用分组不一致；要求历史验收索引不同步不再阻断开发。

## 范围与边界

- 只修改客户端；不修改 NewAPI、数据库、Nginx 或线上设置。
- 版本号是信息，不是白名单。识别真实应用及运行组件，配置按既有格式解析、合并、回读；真实验证失败不能显示已可用。
- 计费分组来自已登录账户的 usable_group 与模型 enable_groups 交集。倍率来自 group_ratio，缺少价格不伪装为 0 或 1。
- 选择具体分组，网络线路独立选择。动态价格按服务端表达式展示估算或规则，不把倍率直接说成官网折扣。
- 密钥按工具与具体分组隔离；不修改旧分组密钥，重复接入复用同组密钥。新建接口即使不返回 key，也通过已有查询/取钥接口继续。
- 激活前重新校验模型和分组，串行执行本机配置事务，回读服务端密钥分组；失败恢复原配置和安全存储，不删除历史密钥。

## 接口变动

- 账户模型增加可选 billing 元数据（分组、倍率、基础美元单价、计费表达式），保留现有账户 schemaVersion 3 的兼容读取。
- 激活输入增加必填 billingGroup；结果增加 billingGroup，schemaVersion 3。缺少运行组件与分组不可用使用明确失败状态。
- 计费表达式只作安全的本地展示解析，不能执行 JavaScript。未知规则不阻断接入，展示原规则和价格待确认。

## 验证计划

1. 新版本、四段版本、未读出版本均不因版本号被拒；缺少真实运行组件不伪装支持。
2. 分组交集、0 倍率、账户专属倍率、缺失价格、模型切换与分组失效。
3. 分组进入激活请求及令牌请求，异组旧令牌不复用；新建成功但无 key 的标准响应。
4. 重复操作、并发保护、外部配置变化、验证失败恢复；秘密不跨渲染器。
5. 动态高峰/非高峰规则、固定价格、按次价格、异常表达式与缓存计价说明。
6. 前端全量测试、类型检查、原生测试、渲染构建及界面实测。
