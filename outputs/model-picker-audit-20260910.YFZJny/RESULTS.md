# 模型选择框：滚动与搜索修复记录

日期：2026-09-10。结论仅针对当前工作区源码，不代表已发布安装包或 Windows 真机已验收。

## 问题与处理

1. 原组件把 `relatedTarget=null` 的失焦直接当作离开组件，会在某些原生滚动条交互中移除整个列表。改用项目已有 Radix 非模态弹出层处理外部交互，移除这种通用失焦关闭逻辑；鼠标拖动完成后恢复输入焦点。不锁定页面点击，不新增依赖。
2. 原输入框没有组合输入保护，中文输入法确认候选字的 Enter、方向键、Escape 可能被当成模型选择操作。现在组合输入期间保留草稿、不更新筛选、不选模型；兼容 compositionend 先于 keydown 且 keyCode=229 的顺序。
3. 原筛选只重置索引，不重置滚动位置，导致看不到第一个匹配项，但回车却会选中它。现在筛选与清空会回到列表顶部；键盘定位只滚动列表，不拖动整个工作台。
4. 支持 `gpt6`、`GPT 6`、全角 `ＧＰＴ　６`、空格/连字符/下划线变体。`GPT 6` 不会因为小版本数字而混入 GPT-5.6。仅检索完整 ID 和受审显示名，不检索私有上游描述，不改写提交给配置的模型 ID。
5. 点击和键盘展开使用一致的查询重置行为；账号模型更新后不会提交旧的活动索引。接入页、模型价格页使用同一组件，查询与选择互不污染。
6. 额外检查发现 Tab 与底部布局问题。弹出内容保留在字段的文档顺序中，滚动容器显式 `tabIndex=-1`，避免浏览器把它当成额外 Tab 停靠点；只有明确 Tab 离开时才在失焦后收起。窗口边界压缩列表后，用列表自身的 ResizeObserver 重新定位当前项，关闭时断开观察器。

## 失败证据与验证过程

- 初始失败用例：`regression-before.json`，18 项失败、10 项通过；其中测试环境缺少 scrollIntoView 的两条未处理异常是 JSDOM 限制，不作为真实设备故障证据。
- 增强 Tab 用例抓到中间实现的焦点问题：`regression-after-2.json`，30 通过、2 失败。后续修复保留这份失败报告，没有覆盖。
- 边界压缩列表的失败用例：`resize-before.json`；最初观察器挂接早于 Radix 内容实际挂载，`resize-after.json` 仍失败。改为随列表 ref 挂接/断开后，`resize-after-2.json` 33 项专项用例全部通过。
- 生产浏览器又抓到可滚动 div 的原生 Tab 停靠行为（JSDOM 的 user.tab 不模拟它）；显式设置列表 tabIndex 后重新实测通过，并补充 DOM 契约断言。
