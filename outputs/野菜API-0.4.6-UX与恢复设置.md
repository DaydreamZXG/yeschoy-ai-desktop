这轮把主要入口改成“我的应用”，补上持久的接入状态、搜索模型、可见的分组选择，以及不需要登录的“恢复原设置”。同时修复登录重试、缓存价遗漏、连接验证过早成功、桥接进程意外退出等问题。

## UX 分析：先让用户知道能做什么、发生了什么、怎么退出

| 原来的问题 | 本轮变化 | 对用户的意义 |
| --- | --- | --- |
| 首页大量指标，接入之后缺少日常管理入口 | 应用卡片优先展示模型、分组、线路与当前本地状态 | 打开就能找到自己使用的应用 |
| “已安装”“写入成功”“实际能用”混在一起 | 区分未发现、待接入、已接入、设置已变更、需要恢复、状态待确认 | 不再把发现应用说成已经连接成功 |
| 应用接入后没有退路 | 卡片和接入页都提供恢复入口 | 不要求继续使用野菜，也不要求先登录 |
| 模型下拉列表难找，计费分组不突出 | 搜索完整模型 ID；模型、分组、网络线路分开 | 选择倍率不会被误认为切换网络线路 |
| 返回页面就丢选择、丢进度 | 保留接入页实例；已接入应用恢复模型、分组和线路 | 可以去看账单、处理登录，再回来继续 |
| 登录一遇到临时错误就停住 | 保留等待状态并重试；取消、退出后的迟到结果不能覆盖新状态 | 少一些“点了没反应”或重新登录的假象 |
| 窗口关闭后桥接端口消失 | 关闭窗口改为最小化；设置页另设“完全退出”确认 | 使用依赖桥接的应用时不会因点关闭而立刻断线 |
| 价格表复杂、缓存价未完整参与计算 | 展示 1 亿 Token 缓存型示例；细节折叠、跟随网站汇率和分组 | 先看到差价，需要核算时仍有计算依据 |

视觉方向借鉴 Cockpit 的固定侧栏、应用卡片和清晰状态层次，不照搬其账号池。按 frontend-design 技能做了实际渲染复查，采用与品牌 Logo 一致的低饱和绿色、浅灰绿色背景，减少大面积装饰。标题使用系统显示字体，中文优先苹方／微软雅黑，模型 ID 使用等宽字体；同时调整深色对比度、字号、控件间距、键盘焦点和小窗口排版。

## 恢复设置如何工作

入口：我的应用 → 对应应用 → 恢复原设置；也可以进入“调整接入”后恢复。

- 新接入：在修改前保存这个应用的一份加密原始设置。后续换模型、换分组仍保留最初的可恢复基线，不积累历史备份。
- 记录以 AES-256-GCM 加密，加密密钥存放在系统安全存储中。原始配置可能含其他服务商的凭据，因此不会以明文备份落盘，也不会发给网页界面。
- 没有外部修改时，恢复原始文件字节；有外部修改时，按字段保留用户后来改过的内容，撤销仍属于本次接入的修改。
- 新建文件只在撤销后没有剩余内容时移除；其他服务商、应用、聊天和网站账户不会被批量删除。
- 多文件先计算恢复计划，再逐项写入与读回。记录损坏、路径不安全、配置无法解析时，保留恢复记录并报错，不猜测原值。
- 接入或恢复被打断，可以依据未完成记录重试。跨进程文件锁避免两个客户端同时生成密钥、写入或恢复。
- 恢复只清理对应工具的本地凭据与助手启动的进程，不远程撤销可能仍被其他设备使用的令牌。

旧版本没有保存原值，**不能完整找回原设置**。此时显示“撤销野菜设置”，只清理能证明属于野菜的连接项；无法证明的第三方配置保留。恢复原服务商的未知原值仍需在目标应用中选择。不会把这种有限撤销包装成完整恢复。

限制：精确恢复保留原文件字节；发生外部编辑后，JSON5／YAML 的合并可能规范化格式或注释。内容保护不等于所有格式都原样保留。系统安全存储不可用时不会退回明文方式。

主要实现：`src-tauri/src/connection_recovery.rs`、`tool_activation.rs`、`tool_adapters/common.rs`；界面：`src/configuration/connections.tsx`、`RestoreConnection.tsx`。

## 价格与连接的可信度修正

价格示例固定为 **1,000 万新输入 + 8,000 万缓存读取 + 1,000 万输出**。缓存读取价优先取网站当前规则；缺少单独缓存价才按输入价保守估算并说明。不另行虚构固定汇率，不把按次计费换算成 Token 价格，不执行服务器返回的任意表达式。

两边使用相同用量结构，野菜一侧再应用所选分组倍率；阶梯规则显示区间。官网参考价仍依赖网站持续维护的基价，这轮没有独立采集各模型厂商的官网报价。示例不是实际账单预测，也没有把默认 80% 缓存率说成每个用户的真实命中率。极小正价格不显示成零，接近 100% 的折扣不会向上取整成免费。

Claude 桥接不能再只收到成功响应头就判为完成：还需要有效内容和完整结束信号，空响应、错误响应和中断流不能算成功。出站客户端禁止跟随重定向，并设置读取超时。Codex 现有验证仍是配置／凭据／选中模型通路检查与桌面启动，不等于已经观察到 Codex 桌面完成完整工具调用。因此成功文案只描述实际验证范围。

## 仍需推进的事项

1. **发布前真实设备验收**：在安装后的 macOS（Intel／Apple Silicon）和 Windows 包中，分别执行登录 → 接入 → 对话与工具调用 → 重启助手／应用 → 恢复 → 原服务商可用。当前隔离测试不能代替这一步。
2. **DSH 日常启动体验**：此次没有加入独立的“打开已接入应用”命令，也没有补上重启助手后自动恢复 DSH 进程。不能据此声称每个工具的整个生命周期已完善。
3. **现有接口契约需要同步**：历史 `desktop-account-session@v3` 的闭合模型描述漏列了早已存在的端点能力和 billing／groups，本轮缓存单价也通过可选字段传递。当前原生端与界面端已配套、已有解码测试，但这不是历史契约已覆盖的证据。应另行追加准确的新版本契约，不改写冻结快照；在此之前不宣称完整架构一致或整体发布就绪。
4. **自动更新**：本轮未开启，更新来源、签名、源提交对应、旧版恢复记录迁移与失败回退仍需单独验收。不要用已有别的版本的包替代新版本验证。
5. **剩余体验**：新工作台文案优先中文，完整多语言还需补齐；慢连接中断、目标应用主动改写配置、系统安全存储弹窗需真实设备走查。

建议下一轮聚焦安装后的“接入—使用—恢复”闭环，先把真实失败定位清楚，再扩展更多工具；当前不建议引入能任意改文件或执行命令的内置 Agent。

## 本轮日常使用 UX 续改（2026-09-05）

### 已落地到本地源码

- 首页默认只显示本机已发现或已接入的应用，其他应用可展开；未登录时不显示一组空的账单指标。
- 已接入的 Claude Desktop、Codex Desktop、DSH 增加独立“打开使用”。原生入口只接受固定工具 ID，不接受命令、路径、URL 或密钥；打开不会签发新工具令牌、提交配置或发送付费模型验证。CLI 工具显示真实的“使用方式”，不伪装成桌面启动。
- DSH 在助手重启后可由“打开使用”重新启动；同一设置和凭据的运行实例复用，直接子进程已经退出则重启。Claude 桥接重复打开不再无故重启。
- 接入页默认聚焦一个应用。安装位置、全部应用和网络线路按需展开，完整模型 ID、计费分组、倍率及一亿 Token 示例保持可见。
- 已保存模型或分组从当前目录消失时保留原名称并要求明确重选，不偷偷切换模型或价格。临时刷新失败也不会用默认值覆盖保存的选择。
- 新接入失败不会再被旧的“已连接”状态覆盖成成功。处理中禁用重复操作，完成结果绑定提交时的应用、模型、分组、线路和前端账户，失败显示具体下一步。
- 修复后台读取与恢复并发时一直显示加载中的问题；迟到的读取不能覆盖恢复结果。成功和失败恢复都有回归测试。
- Codex 打开前核对完整的密钥辅助调用参数，修改为其他工具的参数会被识别，不会误用该工具的凭据。
- 退出确认只列出已知需要助手后台运行的应用；恢复入口保留，不要求先登录。
- 补充准确的本地账户投影 schema 4，未知价格省略、零价格保留；界面兼容旧 schema 3。没有改变网站 API。

本轮继续使用 frontend-design 的应用优先、渐进展开和明确视觉层级原则；没有替换品牌 Logo、添加装饰性大图或任意执行命令的 Agent。
