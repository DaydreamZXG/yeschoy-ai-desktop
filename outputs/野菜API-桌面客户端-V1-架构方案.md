# 野菜API 官方桌面客户端 V1 架构方案

状态：架构草案，供评审；尚未冻结、尚未授权开发  
日期：2026-08-29  
产品标识：`com.yeschoy.desktop`  
上游基线：CC Switch `3.20.1`，提交 `3217f72596f2d1c0f879f0a05f83803825d9809f`

## 1. 结论

V1 直接 fork CC Switch，但不把它简单换皮。保留经过审查的 Tauri/Rust 桌面基础、工具配置读写、路径处理、原子写入、进程检测和打包能力；产品层改造成野菜API的官方客户端，并新增第一方账号、余额用量、模型价格、线路诊断、设备级工具密钥、配置事务、安全存储、遥测和官方更新。

边界必须明确：

- CC Switch 是技术起点，不再是产品信息架构。
- NewAPI 仍是账号、可用模型、计费和用量的服务端事实源，客户端不复制账单逻辑。
- V1 的配置目标为用户已经安装的 Claude Code、Codex、OpenCode、Pi 和 DSH；只有进入精确版本白名单的工具才能写入。DSH 尚无版本通过矩阵时不阻止整体发布，客户端仅只读发现，后续通过签名客户端更新增加正常支持。
- 当前阶段不修改 NewAPI、服务器、Nginx、DNS、数据库或线上配置。
- 没有后端桌面授权和设备工具密钥接口前，可以开发外壳、适配器与离线事务，但不能把完整登录和正式发 Key 宣称为可用。

| 上游能力 | V1处理 | 原因 |
|---|---|---|

| 路径解析、文件读写、JSON/TOML/YAML工具 | 复用并收口 | 是五类工具适配器的底层能力 |
| 原子写入和外部变更检测 | 复用并加强 | 可作为配置事务的写入原语，但不是完整事务 |
| Claude Code、Codex、OpenCode、Pi相关适配代码 | 按工具逐项审查后复用 | 上游行为不能直接等同于野菜API兼容 |
| 工具进程、版本和安装路径探测 | 复用并补测试 | 符合“只配置已安装工具”的V1边界 |

| 日志脱敏原语 | 复用并增加统一敏感数据分类 | 上游已有已知密钥和URL脱敏思路 |

### 3.2 必须重做或隔离

| 上游能力 | V1处理 | 原因 |
|---|---|---|
| 多服务商/provider管理首页 | 替换 | 野菜API是单一官方服务，不让小白理解provider |

| 长期配置备份、导入导出、云同步 | V1移除或编译期关闭 | 已确认不保留备份历史、不做跨设备恢复 |
| 本地代理、复杂路由、故障转移 | V1关闭 | 超出第一版范围，也会扩大安全面 |
| MCP、Skill、Prompt、插件市场等扩展 | V1关闭 | 不是核心问题 |
| 上游OAuth账号、订阅和余额脚本 | 不直接沿用 | 野菜API必须走第一方最小权限接口 |
| 上游数据库中的provider秘密存储方式 | 不作为野菜安全方案 | 野菜账号会话和工具Key必须进入操作系统凭据库 |
| 上游更新地址、公钥、深链scheme、包名、图标和品牌 | 全部替换 | 防止串更、品牌混淆和供应链风险 |

### 3.3 必须新增

- 野菜API设备授权与会话客户端。
- 账号、余额、用量、充值跳转和模型价格投影。
- “账号 × 当前设备 × 工具”的独立Key生命周期。
- 五类工具统一适配器契约和兼容版本表。
- 加密、仅限当前事务的临时回滚快照。
- 分层线路和协议诊断。
- 默认开启但明确告知、可关闭的第一方基础运行遥测。
- 野菜API自有的更新清单、公钥、签名和发布通道。

## 4. 目标模块划分

```text
React 用户界面
  ├─ 首次登录 / 首页 / 工具中心 / 配置向导
  ├─ 模型价格 / 余额用量 / 诊断 / 设置
  └─ 只接收业务DTO，不直接接触文件或完整秘密
                  │ Tauri commands
Rust 应用核心
  ├─ Account Session        设备授权、刷新、退出、撤销状态
  ├─ NewAPI Gateway         统一服务端访问、版本与错误映射
  ├─ Catalog & Pricing      模型兼容、推荐、基准价/实际价投影
  ├─ Tool Registry          工具发现、版本和能力矩阵
  ├─ Tool Adapters          Claude/Codex/OpenCode/Pi/DSH
  ├─ Config Transaction     预览、快照、写入、回验、恢复
  ├─ Diagnostics            线路、凭据、模型、协议分层诊断
  ├─ Credential Vault       系统凭据库中的会话、Key与快照密钥
  ├─ Telemetry Pipeline     本地白名单、脱敏、队列与上传
  ├─ Update Trust           签名更新检查、下载与验证
  └─ Local State            非秘密状态、目录缓存、操作日志
                  │
操作系统 / 第三方工具配置 / 野菜API第一方服务
```

### 4.1 单一职责与权威

| 事实 | 唯一权威 | 客户端允许缓存什么 |
|---|---|---|
| 账号、余额、账单、实际可用模型 | NewAPI服务端 | 带时间戳的只读投影；离线时必须显示过期 |
| 官网基准价数值、用户实际价数值 | NewAPI受控定价数据与计费规则 | 带价格版本的显示投影，不另建数字价表 |
| 工具兼容、推荐、中文说明、价格来源 | 版本化野菜模型目录 | V1可随签名安装包携带；以后由接口下发 |
| 当前工具配置 | 工具自己的配置文件 | 只保存野菜拥有字段的哈希、版本和操作结果 |
| 账号会话与工具Key | 服务端状态 + 本机系统凭据库 | 不进入普通SQLite、日志或UI状态持久层 |
| 更新可信性 | 安装包签名 + Tauri更新签名 | 仅嵌入更新公钥，不保存签名私钥 |

## 5. Rust核心接口边界

### 5.1 `AccountSession`

负责设备码申请、轮询、访问令牌刷新、30天不活跃/90天绝对重新授权、退出和撤销状态。UI只得到 `LoggedOut`、`WaitingForBrowser`、`Authorized`、`Expired`、`Revoked`、`Offline` 等状态，不得到refresh token。

禁止：复用网站Cookie、在WebView内收集密码、把令牌放进URL、让前端JavaScript持久保存长期凭证。

### 5.2 `NewApiGateway`

所有第一方请求由一个网关发出，集中处理：

- 两条官方线路和最终协议路径。
- 设备会话认证与刷新互斥。
- 请求ID、超时、重试资格和错误码映射。
- 服务端时间、数据版本、过期状态和撤销响应。
- 响应字段白名单，防止服务端错误内容把秘密带入日志。

UI、适配器和遥测不得自行拼接NewAPI请求。

### 5.3 `ToolAdapter`

五类工具必须实现同一契约，不能在页面组件中写工具特例：

```text
identity()                  稳定tool_id、展示名、图标
detect()                    安装路径、版本、运行状态、候选配置目录
capabilities(version)       协议、模型目录、重启要求、密钥存储方式
inspect()                   解析配置，返回野菜字段和冲突，不返回完整秘密给UI
plan(desired_state)         生成精确变更计划，不落盘
validate_plan(plan)         语法、所有权、路径和版本校验
apply(transaction)          只通过Config Transaction写入
read_back()                 重新读取并比较目标状态
probe()                     发最小、无用户内容的协议请求
remove(plan)                只移除野菜拥有字段
```

统一返回状态：`not_found`、`unsupported_version`、`unconfigured`、`healthy`、`needs_repair`、`external_conflict`、`permission_denied`、`recovery_required`。

### 5.4 `ConfigTransaction`

这不是普通“保存文件”。每次修改固定执行：

```text
锁定同一工具事务
→ 扫描目标文件、权限、身份和内容哈希
→ 适配器生成拟写入内容和字段级摘要
→ 用户确认
→ 用系统凭据库中的临时密钥加密快照
→ 写入事务日志“prepared”
→ 再次检查外部变更
→ 原子写入
→ 重新读取、解析和字段级比对
→ 最小连通性测试
→ 成功：标记committed并删除快照
→ 失败：恢复、回验、标记rolled_back并删除快照
```

若崩溃，只允许遗留 `prepared` 或 `written` 的未完成事务。下次启动先进入恢复页，不继续新写入。恢复失败时保留加密快照和操作编号，直到恢复成功或用户明确放弃；不能把它变成长久备份功能。

### 5.5 `CredentialVault`

**已确认安全边界**：以操作系统安全存储为唯一秘密存储：macOS Keychain、Windows Credential Manager/DPAPI封装。具体Rust库待安全评审后选定；当前CC Switch依赖中未观察到可直接当作该边界的凭据库实现。

记录分开命名：

- `account/device-session`：长期设备会话。
- `tool-key/{tool_id}`：当前设备对应工具的relay key。
- `rollback-key/{transaction_id}`：当前配置事务的临时加密密钥。

普通SQLite只存引用、掩码后四位、服务端Key ID、创建时间、状态和哈希，不存完整秘密。系统安全存储不可用时，登录可降级到重新授权，但任何需要落地秘密或创建回滚快照的配置写入必须被阻止。

## 6. 五类工具的V1适配边界

| 工具 | 目标文件/位置 | V1所有权 | 冻结前必须验证 |
|---|---|---|---|
| Claude Code | `~/.claude/settings.json` | 野菜Base URL、已选模型映射；已确认用`apiKeyHelper`引用系统凭据库 | Windows/macOS路径、最低CLI版本、外部凭据覆盖、运行中重载行为 |
| Codex | `~/.codex/config.toml`；官方登录缓存只读保护 | 野菜provider、Responses协议；已确认用provider `auth.command`引用系统凭据库 | 最低CLI版本、helper路径稳定性、不破坏官方登录、重启要求 |
| OpenCode | `~/.config/opencode/opencode.json`中的野菜provider、默认模型与野菜认证插件项 | 不在`options.apiKey`或`auth.json`写野菜Key；已确认由认证loader运行时调用helper | 最低版本、插件加载、配置优先级、稳定安装路径 |
| Pi | `~/.pi/agent/models.json`中的显式野菜provider；可选`settings.json`默认模型 | `apiKey`只写原生`!helper`命令，不接管Pi `auth.json` | 最低版本、跨平台命令转义、默认模型冲突、工具级请求 |
| DSH | `web` profile 的`$DSH_HOME/settings.yaml`、profile patch和固定插件依赖 | 已确认V1只自动配置`web`；精确版本通过矩阵后按正常V1支持展示且不加Developer Preview产品标签；未通过时只读且不阻止整体发布；settings只写凭据引用；已确认以野菜OS-vault provider替换默认文件凭据provider | 完整credential service、非野菜凭据兼容、升级行为；其他profile只读发现 |

表中路径和方向来自当前资料，只是候选契约。每个适配器进入开发前必须用受支持版本建立“最小原始配置、已有第三方配置、损坏配置、外部并发变更、卸载后残留、权限不足”样本库。

Claude Code与Codex的逐字段边界、线路派生、状态和凭据助手规则见[Claude Code与Codex适配契约草案](./野菜API-V1-工具适配契约-Claude-Code与Codex.md)；OpenCode、Pi与DSH的安全接入层级见[OpenCode、Pi与DSH适配契约草案](./野菜API-V1-工具适配契约-OpenCode-Pi与DSH.md)。两份文档仍为草案；产品已确认“不明文回退”，但最低版本、插件/provider实现和实机验收尚未完成，不得把任何工具标记为冻结或已经兼容。

## 7. 关键运行流程

### 7.1 第一次登录与配置

1. UI展示遥测说明和开关，但不阻塞核心功能。
2. 客户端申请一次性设备授权码，系统浏览器打开第一方授权页。
3. 授权完成后，设备会话进入系统凭据库；客户端拉取账号摘要和服务端能力。
4. 扫描五类工具；用户只看到已安装、未发现或版本不支持。
5. 对两条线路测试DNS、TLS、HTTP和最小鉴权前探测，给出推荐但不自动改配置。
6. 用户选工具和模型，看到真实ID、兼容性及官网价/野菜实际价。
7. 服务端为当前设备和工具创建或复用独立Key；完整Key只进入Rust内存和系统凭据库。Claude Code、Codex与Pi通过各自支持的命令式凭据接口按需读取；OpenCode与DSH使用经过版本验证的野菜认证组件。普通配置只保存不含秘密的helper、插件或credential reference；安全组件不兼容时不降级为明文写Key。
8. 配置事务完成预览、快照、写入、回验和最小协议测试。
9. 只有真实测试成功才显示“已经可以使用”。

### 7.2 线路切换

线路测试只是建议。用户确认后，适配器以同一个工具Key和模型执行一次完整配置事务；两条线路不得造成重复Key或价格变化。

### 7.3 工具Key轮换

服务端先生成替代Key，旧Key继续有效。客户端保存新Key并完成配置事务和验证；成功后才通知服务端撤销旧Key。失败则恢复旧配置、撤销未启用的新Key并保留旧Key。

### 7.4 退出与设备撤销

- 客户端退出：删除本机账号会话，不擅自删除工具配置或工具Key。
- 网站撤销设备：设备会话和该设备全部工具Key失效；客户端下次联网进入明确的“设备已撤销”。
- 本地移除野菜配置：单独询问是否撤销对应远端工具Key。

## 8. 本地数据边界

### 8.1 可以进入普通本地数据库

- 应用设置、遥测开关、主题和语言。
- 已发现工具、版本、配置路径的规范化标识。
- 模型目录版本、价格版本、数据更新时间。
- 配置操作编号、阶段、结果、错误码和目标字段哈希。
- 工具Key的服务端ID、掩码、状态，不含完整Key。
- 未完成事务的加密快照路径和状态。

### 8.2 不得进入普通数据库、日志或前端持久层

- 账号refresh token、完整工具Key、快照解密密钥。
- 网站Cookie、密码、支付资料。
- 用户提示词/响应、项目内容、剪贴板。
- 完整配置文件正文、完整路径中的用户名、原始崩溃内存。

### 8.3 日志与导出

日志采用事件码和字段白名单。路径在采集前去用户名并归一化，密钥按精确已知值脱敏；导出诊断包前进行第二次扫描，用户预览后才保存。遥测与账号/设备授权身份不建立可逆关联。

## 9. Windows与macOS架构取舍

核心业务和适配器共享Rust实现，平台差异收口到 `PlatformServices`：凭据库、文件权限、进程发现、默认浏览器、安装路径、签名和更新。

### macOS

- 目标：macOS 13+，Intel与Apple Silicon Universal构建。
- 官网发布Developer ID签名、公证DMG，不进入Mac App Store。
- 更新包同时受Apple代码签名和野菜更新签名保护。
- Keychain访问、沙盒外配置目录权限和公证安装包必须在干净机器验证。

### Windows

- 目标：Windows 10 22H2 x64和Windows 11 x64；Windows 11 ARM64通过x64模拟仅尽力支持。
- 依赖WebView2；缺失时只使用微软官方安装路径。
- 无可信代码签名时不向小白公开发布。组织发布者优先，个人发布者可作退路。
- 官网签名安装包与Store MSIX两条路线暂不冻结；两者都必须验证更新、权限、Credential Manager和配置目录行为。

## 10. 更新与供应链安全

fork后的第一项发布工程任务是断开所有上游发布身份：

- 包名改为 `com.yeschoy.desktop`，产品名、scheme、图标和窗口身份改为野菜API。
- 删除CC Switch更新端点和上游更新公钥，未配置野菜更新公钥前关闭自动更新。
- 更新清单只放版本、平台、下载URL、哈希、签名、发布时间、最低兼容版本和发布说明。
- 更新签名私钥、Apple签名/公证凭据、Windows签名凭据分别保管，不能写入仓库或客户端。
- 更新采用“下载后验签、安装前确认”；严重安全更新可以强提示，但不能绕过验签。
- 上游合并通过专门评审分支，先看配置格式、安全、遥测、代理和更新相关差异，再决定摘取；不自动追随上游主分支。
- 每次发布生成依赖清单/SBOM并完成许可证审计。CC Switch MIT声明随发行保留；不得把NewAPI的AGPL服务端代码复制进客户端而不做单独许可证评审。

## 11. 遥测架构

遥测默认开启，但首次上传前以通俗文案明确告知并提供关闭入口。事件只能由Rust核心从固定枚举生成，前端不得提交任意JSON或错误正文。

允许：应用/构建/通道、系统/架构、工具/版本/适配器、操作阶段/结果/错误码/耗时、线路类别、模型ID、脱敏后的崩溃指纹和代码栈、30天轮换的遥测ID。

禁止：秘密、提示词、响应、项目与配置内容、完整路径、系统用户名、剪贴板、原始内存转储。

本地队列最长7天；关闭时立即清空。服务端普通事件30天、脱敏崩溃90天、不可逆聚合12个月。遥测接收端与账号接口逻辑隔离，不接收账号Bearer token或网站Cookie。

## 12. 测试与发布门槛

### 12.1 适配器门槛

- 每个受支持工具版本都有真实安装和样本配置证据。
- 新文件、已有配置、损坏配置、只读文件、外部并发修改、工具运行中、断网和余额不足都可重复测试。
- 写入只改变野菜拥有字段；快照创建、恢复和删除可验证。
- 连通性测试不发送用户数据，也不会造成不可忽略的计费。

### 12.2 安全门槛

- 静态和运行时检查证明日志、遥测、崩溃包不含完整Key与会话。
- 系统凭据库不可用时不会退化为明文。
- 更新源、公钥、包名和深链不再指向上游。
- macOS签名/公证和Windows可信签名在干净机器可验证。

### 12.3 服务端契约门槛

- 对实际部署NewAPI做只读契约审计，而不只看GitHub源码。
- 设备授权、窄权限会话、设备工具Key和撤销级联完成服务端实现及安全测试。
- 价格接口能提供与账单一致的基准/实际价投影，复杂计费不要求客户端执行服务端表达式。
- 用量能按工具Key、模型和时间查询；线路归因若无法可靠获得，界面不伪造。

## 13. 尚未冻结的事项

这些事项会阻止“完整V1架构冻结”：

1. 五类工具首批受支持版本和逐字段配置契约；产品已确认采用通过完整矩阵的精确版本白名单，候选集合与52个基础平台版本单元见[工具版本支持与验证矩阵草案](./野菜API-V1-工具版本支持与验证矩阵.md)。DSH已确认V1只支持`web` profile自动配置，其他profile只读发现。
2. 首批模型清单、五类工具兼容矩阵及推荐标签。
3. 实际部署NewAPI的版本、定制差异、认证方式和响应契约。
4. Windows官网签名安装包还是Store MSIX，以及最终签名身份。
5. 更新签名私钥、Apple/Windows发布凭据的保管人和事故流程。
6. 性能、启动、扫描、配置和诊断的可测目标；没有测量前不编造数字。
7. 未来NewAPI接口方案评审、数据库迁移与灰度顺序。

## 14. 可以先行、但不代表完整产品可发布的工作单元

待正式授权开发后，可先做不依赖线上改造的封闭单元：

1. 建立野菜fork、保留MIT声明并隔离上游发布身份。
2. 建立五类工具统一适配器契约和只读发现器。
3. 建立配置计划、原子写入、加密临时快照与崩溃恢复的离线测试框架。
4. 建立登录、首页、工具中心、配置向导的假数据原型。
5. 建立服务端接口类型和本地模拟器，但明确标为mock，不连接生产。

完成这些单元仍不等于账号登录、发Key、计费展示或正式发布已经就绪。
