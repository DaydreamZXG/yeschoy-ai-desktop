# 野菜API 通用兼容策略验证

日期：2026-09-04。范围仅限桌面客户端；没有修改 NewAPI、数据库、Nginx、DNS 或线上服务器配置。

## 当前线路

- 大陆优化：`https://yeschoy.com`
- 全球加速：`https://yeschoy.pro`
- `https://api.yeschoy.com` 暂不进入可选线路、登录、诊断、密钥或自动回退逻辑。待服务恢复后先独立验证 TLS、桌面登录契约、模型接口和真实请求，再决定作为第三条线路还是替换现有全球线路；客户端不会静默跨域重试写操作。

两条当前线路均已只读确认主页返回成功，未登录访问模型接口返回 401，符合需要密钥的边界。切换线路时，登录会话继续由最初签发会话的线路刷新；另一条线路暂时拒绝访问令牌只显示线路不可用，不会清除本机登录。

## 七种接入目标

客户端当前明确识别并尝试接入 Claude Code、Claude Desktop、Codex Desktop、Pi、DSH、Hermes（爱马仕）和 OpenClaw（小龙虾）。版本号只用于展示，不再作为白名单；是否可用由应用身份、所需运行组件、配置解析与回读、以及该工具自己完成真实回复共同决定。

- 每次接入先读取现有配置，只合并野菜API拥有的字段。
- 密钥保存在 macOS Keychain 或 Windows Credential Manager；普通配置只保存安全引用。DSH 仅在受控子进程环境中收到密钥。
- 写入、回读、启动或真实请求任一步失败，恢复原配置和原安全存储；仅删除本次可证明新建的服务端令牌。
- Hermes 使用当前 `providers` 配置和 `key_cmd`；OpenClaw 使用 `models.providers` 与 exec SecretRef；DSH 使用当前 `llm-pi-ai.providers` 配置并先完成无工具真实回复。

Hermes 与 OpenClaw 本轮完成了配置合并、秘密引用、回读和失败恢复的原生测试，但本机未安装这两款工具，因此不能把契约测试写成真实账户端到端通过。Pi 0.84.4 与 DSH 0.1.2-rc.1 已核对为当前安装源的最新版。
