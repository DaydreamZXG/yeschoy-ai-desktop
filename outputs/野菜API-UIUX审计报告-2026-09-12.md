## 〇、审计总评

产品骨架健康：双主题 token 基座完整、对比度全部达标、reduced-motion 基建与测试保护已就位、无 JS 动画债。但有四处"显性伤口"需要优先处理：

1. **可访问性断裂（最高危）**：shadcn 组件依赖的 `--primary/--card/--ring/--border` 等变量**全项目从未定义** → 所有 shadcn 按钮键盘焦点完全不可见、Tooltip/Card/Badge 底色透明失效，涉及 15+ 使用处。
2. **品牌事故**：应用标题、首次运行弹窗、设置页数十处仍自称"CC Switch"；且安装页与接入页对"是否发送计费测试消息"的口径**互相矛盾**，直接损害扣费信任。
3. **国际化断裂**：主接入流程（ConfigurationPreviewView 及 7 个关联组件）约 50 处中文硬编码绕过 i18n，英文界面下主流程满屏中文。
4. **动效空白**：全产品在跑动效仅 3 处（按钮 hover、两个旋转菊花），核心路径"选分组 → 选线路 → 一键接入 → 成功"全部生硬跳变；tailwindcss-animate 疑似缺失导致 Radix 弹层瞬开瞬关。

另有一个**架构级前提矛盾**需要决策：`tauri.conf.json` 实际窗口为 1120×760（min 860），但 CSS 存在约 250 行 ≤720px 窄窗媒体查询且测试断言 `min-width:320px/max-width:420px` —— 窄窗适配层在当前生产形态下全部为死代码。

## 二、布局结构专项摘要

**体系健康度**：CSS 处于"双文件并存"转型中期。token 基座质量不错（现代实践齐全：focus-visible / reduced-motion / pointer:coarse），但 v2 以约 50 组同名选择器压覆 index.css，最终样式依赖导入顺序——**本次审计近半数布局问题由此派生**（死规则、死属性、修复未生效）。

**确定的用户可见问题**：
- `.connection-selection-flow strong` 换行修复未生效（P0-6），用户看不清已选模型全名；
- 若目标窄窗 320px：`.price-pair` 双列价格**确定性横向溢出**（grid 轨道被长数字撑破），首页步骤条超出可用宽度；
- 9px 微字号出现在价格/省钱金额等关键信息上，低于桌面可读性下限。

**关键决策请求**：窗口形态二选一（320-420 窄窗 vs 当前 860+ 桌面窗），决定 250 行媒体查询与相关测试断言的去留。

## 四、动效方案（完整版）

### 4.1 设计原则

1. **功能优先，动效即反馈**：每处动效必须回答"状态发生了什么变化"；
2. **快入快出**：反馈 ≤200ms，过渡 ≤300ms，任何动效不阻塞操作；
3. **只有一处仪式感**：全产品仅"一键接入成功"一个高潮（≤640ms），稀缺性产生对比；
4. **只用合成层属性**：动画只碰 transform/opacity；
5. **尊重系统偏好**：reduced-motion 下保留状态可感知，移除位移/缩放/循环。

### 4.2 Token 体系（落地 tokens.css，纯增量）

```css
:root {
  --dur-instant: 80ms;  --dur-fast: 140ms;  --dur-base: 200ms;
  --dur-slow: 300ms;    --dur-ritual: 640ms;
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in: cubic-bezier(0.64, 0, 0.78, 0);
  --ease-in-out: cubic-bezier(0.45, 0, 0.15, 1);
  --ease-spring: cubic-bezier(0.34, 1.4, 0.64, 1);
  --ease-press: cubic-bezier(0.3, 0, 0.5, 1);
  --tr-color: color var(--dur-fast) ease, background var(--dur-fast) ease, border-color var(--dur-fast) ease;
  --tr-fade: opacity var(--dur-base) var(--ease-out);
  --tr-pop: transform var(--dur-base) var(--ease-spring), opacity var(--dur-base) var(--ease-out);
}
```

### 4.3 "一键接入"仪式感动效（四拍编排）

直接映射 `useActivationTask` 的 `idle/applying/finished` 状态机：

1. **触发（0→160ms）**：按钮 `scale(0.97)` 下沉确认；ArrowRight 交叉淡出、LoaderCircle 回弹淡入开始旋转；
2. **进行（时长不定）**：菊花旋转提速至 900ms；按钮底部 2px 不确定进度条循环（transform scaleX+translateX）；progress 事件映射阶段文案轮换（"写入配置 → 校验线路 → 生效中"）；
3. **成功（0→640ms，全产品唯一高潮）**：按钮变 `--success` 绿 → CheckCircle2 回弹进入 → 一圈同色光环扩散淡出（scale 1→1.35, opacity→0）→ 成功横幅 fade+translateY(6px→0) 进入，三拍交叠；
4. **收尾**：绿色态保持 ~1.2s 后自然过渡为"已接入"常态样式；成功横幅常驻供阅读。失败路径不走仪式：按钮恢复 + 错误横幅进入 + 一次 ±3px 水平轻晃。

关键 CSS 草案（完整版含降级）已在子调研中给出，对比原型 `prototypes/one-click-access-comparison.html` 可交互演示。

### 4.4 其余场景

| 场景 | 方案 |
|---|---|
| 面板切换 | 旧 fade-out 120ms + 新 fade+translateY(4px→0) 200ms，不做横向滑动 |
| 卡片选中态 | `--tr-color` + 勾角标 icon-pop 回弹 |
| Radix 弹层 | 修复 animate 缺失后：overlay fade 200ms，content zoom 0.96→1 + fade 200ms |
| Toast | 进入 translateY(8px→0)+fade 200ms spring；成功图标 icon-pop |
| 连接状态点 | 连接中 1.6s 呼吸（仅 opacity），成功后停止 |
| 骨架屏 | opacity pulse 1.4s（唯一允许的循环动画之一），骨架→内容交叉淡入 200ms |

### 4.5 性能规范

- 动画属性白名单：`transform`、`opacity`；`background/border-color` 仅限 ≤200ms transition；**禁止 box-shadow 动画**（现状按钮 140ms 含 box-shadow，建议改伪元素 opacity 阴影）；
- 禁止 width/height/top/left 动画（shadcn accordion 的 height keyframes 不要启用）；
- `will-change` 仅仪式动效 640ms 期间使用，结束即移除，同屏 ≤3 个；
- 同屏进行中动画 ≤5 个（本方案峰值 3）；无限循环动画同屏 ≤2 个；`backdrop-filter: blur` 全屏仅弹窗 overlay 一处。

## 五、实施指南（分阶段）

### 阶段一：止血（P0，全部低成本）
1. 补 shadcn token 层（`:root` + dark 各约 8 个变量，映射现有语义色）→ 一次性解决 #1/#2；

3. `connection-selection-flow` 换行修复（v2 加 3 个属性重置）；
4. 验证 tailwindcss-animate 缺失（`pnpm dev` 开弹窗看类是否生成），缺则补依赖。
**验收**：键盘 Tab 走一遍主流程焦点可见；安装页/接入页口径一致；长模型 ID 完整换行。

### 阶段二：核心体验（P1，动效 + 品牌）
5. 动效 token 落地 tokens.css（零风险纯增量）；
6. 一键接入四拍动效 + ActivationFeedback 进入动画（CSS 为主 + 复用既有 phase 状态机）；
7. 品牌视觉：brand-mark 深色适配、choice-number 改 `--on-accent`、位图图标容器圆角打底；
8. i18n 抽取：ConfigurationPreviewView 50 处硬编码中文入 zh.json/copy 对象；
9. 术语对照表全量替换（可用脚本辅助 + 人工复核）。
**验收**：双主题各走一遍核心路径；reduced-motion 下状态仅靠颜色/文案/静态图标可完整感知；`Workbench.test.tsx` 通过。

### 阶段三：体系化（P2，随迭代）
10. 窗口形态决策 → 媒体查询清理或实测；
11. CSS 架构合并（index 只留 token+基础，组件归 v2），删除死规则/死 token；
12. 间距/圆角/字号/阴影/z-index token 化，渐进替换；
13. 标点/人称/汇率参数化等文案收尾；
14. 骨架屏体系、面板切换过渡。

### 用户测试验证建议
- **5 人走廊测试**：给新老用户各布置"完成一次接入"任务，观察是否在分组/线路/按钮三处产生迟疑；
- **口径信任验证**：直接问测试者"点击一键接入后会不会扣费"，检验计费口径统一效果；
- **reduced-motion 走查**：系统开启减少动态效果后完成全流程，确认无信息丢失；
- 每阶段上线前跑 `pnpm typecheck` + 正常环境补跑 `pnpm test:unit`（注意：本 worktree vitest 挂起是已知环境坑，需换环境）。
