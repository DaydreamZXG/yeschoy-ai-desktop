# 野菜 API 0.4.8：多模型、连接错误与退出修复

本次只修改客户端源码并做本地验收。没有制作安装包、签名、上传、发布，也没有修改服务器或 NewAPI，没有读取真实用户密钥、改写用户应用配置或发起付费模型请求。版本仍为待发布的 0.4.8；已有安装包不包含这次修改。

## 修复内容

### 模型名称与多模型切换

- Claude Desktop 的接入配置使用真实模型 ID，不再把其他模型写成 Sonnet 别名。最近连接结果也显示实际转发的模型 ID，而不是采用 AI 的自我介绍。
- 增加“常用模型”列表。每个模型明确绑定一个计费分组，用户选择默认模型后保存；不会擅自加入账户的全部模型、选择便宜分组或失败后换组。
- Claude Code、Claude Desktop、Codex Desktop、Pi、DSH、Hermes、OpenClaw 的配置适配器均支持模型列表。已有列表中的模型可通过应用自身的菜单或命令切换；首次接入、新增模型或修改目录后，某些应用仍需重新打开才能载入。
- 旧版 Claude Code 缺少可选的模型菜单时，不因此禁止默认模型使用。各应用实际可用的菜单/命令仍取决于其能力。
- 接入时只对默认模型发送验证消息，其他成员明确显示为已配置、尚未逐一测试。不能把目录中出现等同于已验证可用。
- 同一个模型只保留一个计费分组，避免应用只发送模型 ID 时无法确定价格。模型 A/B 分别选用自己的密钥；正在进行的请求保持原来的绑定，更新只影响新请求。

AI 在旧会话里继续自称 Claude，可能受已有上下文或第三方应用提示影响。本次没有伪造回复，也没有整体替换第三方系统提示词。真实的请求模型 ID 可以核对，但它也不能单独证明上游的底层模型权重身份。

### 失败详情与全球线路

- HTTP 失败、超时、流式错误、截断回复不再被当成正常完成；把上游流式错误转换成应用能识别的错误。
- 提供“最近连接结果”：实际转发模型、计费分组、线路、HTTP 状态和简短失败原因。仅保留本次运行中每个应用的最近一条结果，不保存对话、原始上游错误、密钥或供应商内部描述。
- 对经过核对的 GPT 模型处理其不支持的请求参数；不对未知模型套用同一规则，不猜测上游未声明的协议，也不自动重试付费请求。
- 模型回复的读取空闲超时从 60 秒调整为 600 秒，连接建立仍有 15 秒限制；这不是响应时间承诺。

用户截图只有“Request failed · retrying (1/10) · 1m3s”，不能据此确定全球线路失败的唯一原因。两个公开站点接口能响应，也不能证明特定模型、分组和流式会话已经打通。真实账户下的全球线路 GPT 对话仍需后续实测。

### Windows 退出与设置恢复

- 关闭窗口弹出明确选择：后台运行、取消、完全退出；设置页保留完全退出入口。
- 完全退出后停止助手拥有的连接服务；不会强制结束 Claude、Codex 等第三方应用。
- 接入过程中退出，先安全结束已发出的账号操作、恢复未完成的本地设置，再关闭服务。等待较长时显示进度和可继续操作的提示，避免永久卡在禁用按钮。
- 新的多模型接入依赖助手后台转发，界面明确说明：完全退出会暂停连接，原应用随时可以恢复原设置，不会锁定用户。

### 密钥安全

- 模型分组密钥只存系统凭据库，不发送到页面，也不生成明文备份文件。
- Windows 凭据条目较小时使用分段存储，完整写入并校验后才发布新版本；失败时保留或恢复旧版本。测试包含分段失败、更新期间读取和事务取消恢复。
- 本地入口有独立凭据和模型白名单；不把密钥随重定向发给其他站点。
