# 野菜 API：Codex 路由证明与 CLI 运行时修复

## 结论

- Codex 的官方登录保留在原应用中，野菜只接管模型请求的自定义 Provider。官方账号仍显示是正常的身份状态，不能用来判断本次请求由谁计费。
- 客户端现在把本地桥实际收到的请求显示为“最近野菜中转记录”。只有出现这条记录，才会标记“已确认经野菜中转完成”，并展示实际转发的完整模型 ID。
- `gpt-6-astra` 仍按完整 ID 转发，模型目录显示名仍为 `GPT-6 Astra`。Codex 状态栏自行缩写为“6 Astra”不再被当成路由或模型身份依据。
- DSH“打开使用”无反应的根因是 macOS 图形应用 PATH 中找不到 npm 包装器所需的 Node；不是 DSH 配置未保存。

## 修复

- CLI 发现继续按规范路径去重，但保留实际发现的 npm/Node 包装器，不再把它替换成包内 JavaScript 文件。
- 每个子进程只在自己的 PATH 前置包装器及有界符号链接链的父目录；不修改野菜助手或系统的全局 PATH。
- DSH 使用当前规范入口 `dsh --profile web`，启动等待限制为 15 秒，只接受 `127.0.0.1`、`localhost` 或 `::1` 的环回地址。
- DSH 接入和日常打开都不会发送收费的测试提示词；首个真实请求由最近中转记录确认。
- 同一运行时处理复用于 Claude Code、Pi、Hermes、OpenClaw 的隔离验证和 macOS 终端打开流程，避免下一个 Node 型 Agent 重复出现同类故障。

## 验证

- Rust 原生测试：479 项通过。
- 前端单元测试：454 项通过。
- TypeScript 类型检查、Prettier、Rustfmt、Clippy（warnings as errors）通过。
- 真实安装的 DSH `0.1.2-rc.1` 在受限桌面 PATH 等价环境下成功返回本地环回工作台地址；测试后已立即停止，未调用模型。
- Apple Silicon 与 Windows x64 均完成只编译检查；未创建安装包、更新清单或发布资产。

## 本轮边界

本轮没有修改服务器、NewAPI、账号、余额、计费、DNS、远程更新源、版本号或发布资产，也没有覆盖 Codex 的官方登录。安装包将在后续所有小问题确认完成后统一生成。
