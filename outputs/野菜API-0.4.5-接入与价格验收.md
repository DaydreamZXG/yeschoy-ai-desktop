# 野菜API 0.4.5 接入与价格验收

## 本次范围

- 仅修改桌面客户端；未修改 NewAPI、数据库、Nginx、DNS 或线上配置。
- 修复 Codex Desktop 在大陆优化与全球加速线路下一键接入后被统一误判为失败的问题。
- 将逐项单价表收敛为一个可复算的“1 亿 Token 官网预计 / 野菜预计”示例。

## Codex Desktop 接入

原验证流程会启动一次完整的通用 Agent 会话，并把模型是否按预期输出完整事件流当作接入门槛。模型临时发起工具调用、上游事件形态差异或偶发繁忙都会被压成同一个失败提示，配置随后回滚，因此用户看到两个线路都失败。

0.4.5 改为验证接入真正依赖的能力：

1. 当前 Codex Desktop 自带运行时存在；普通版本号不再作为门禁。
2. Codex 的命令式密钥助手能够从系统安全存储读取刚写入的专用密钥，配置文件中不保存明文密钥。
3. 使用所选模型经实际配置的提供方路径完成一次有边界的 Responses 请求。原生 Responses 模型直连所选野菜线路；Chat Completions 模型走仅监听 `127.0.0.1` 的本地转换层。
4. 仅在验证成功后启动 Codex Desktop；任何失败仍恢复原配置、原安全凭据和原本地桥接状态，并仅删除本次已证明由客户端新建的令牌。

失败原因已拆分为密钥读取、认证失败、接口不可用、超时、服务繁忙、模型拒绝、服务不可用和响应格式异常，界面会给出对应操作建议。

## 1 亿 Token 价格示例

固定示例为：

`1,000 万新输入 + 8,000 万缓存读取 + 1,000 万输出 = 1 亿 Token`

- 官网预计：使用 NewAPI 持续维护的模型基础价或计费表达式档位，再乘 NewAPI 返回的正汇率。
- 野菜预计：官网预计再乘用户所选计费分组的实际倍率。
- 多个请求档位：显示最低至最高区间，不伪装成一个固定价。
- 没有独立缓存读取价：缓存部分按输入价保守估算并明确提示。
- 汇率、倍率或 Token 单价不足：不猜价格，显示暂不可估算；不阻止一键接入。

界面仅保留两个主要金额、节省比例与一行复算说明，不再展示输入、输出、缓存读写的逐项单价表。
