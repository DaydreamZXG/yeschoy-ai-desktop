## 三、#2 诊断分层（PRD 6.7）

原诊断仅「DNS / TCP」2 层；本批补齐 TLS 握手层与 API Key 有效性层，并改为**按层三态**展示。

### 契约（`src-tauri/src/connectivity_core.rs`）

- `CONNECTIVITY_LAYER_IDS = ["dns", "tcp", "tls", "api_key"]`（执行顺序固定）。
- `LayerStatus { Passed, Failed, Skipped }`（三态）。
- `LayerReasonCode`：各层细分原因码（DNS/TCP/TLS/API Key + 跳过码）。
- `ConnectivityLayerResult { layer, status, latencyMs?, reasonCode }`、`ConnectivityLineResult { lineId, displayName, rootUrl, host, port, layers }`。
- 新增单测：分层目录顺序固定不变。

### 执行（`src-tauri/src/connectivity.rs`）

- 按层执行 **DNS → TCP → TLS → API Key**；**上游失败则下游自动标记为 `skipped`**。
- **TLS 层**：复用 reqwest/native-tls 完成证书链与有效期校验（任何 HTTP 响应即代表握手通过），按证书错误 / 握手失败 / 超时细分原因码。
- **API Key 层**：`GET /api/user/models`，返回 401/403 判失败、否则通过；**只探测有效性，不消费额度**。
- 新增响应字段 **`schema_version: 2`** 区分新旧契约。
- 会话复用（`src-tauri/src/account_v2.rs`）：新增 `shared_http_client()` / `has_stored_session()` / `native_probe_access(...)`；**无保存会话时 API Key 层自动置为 `skipped`**。
- 测试 fixture 序列化校验与新契约一致。

### 前端

- **`src/diagnostics/contract.ts`**：改为 `layers` 契约 + 严格守卫——校验层数/顺序、`status` 与 `reasonCode` 必须自洽、`latencyMs` 范围、拒绝注入字段（token/URL 等仅出编译期常量）。新增 `lineOutcome()`（取首个失败层推导结论）与 `lineNetworkHealthy()`（**网络层与 API Key 层解耦**：会话失效不算线路不可达）。
- **`src/diagnostics/DiagnosticsView.tsx`**：
  - 逐层展示三态（通过/失败/跳过）+ 延迟 + 原因文案；
  - `api_key` 层失败时挂接修复动作「重新登录」；
  - 新增「复制诊断报告」按钮 → `buildSanitizedReport()` 输出**脱敏文本**：仅线路展示名 + 层 + 状态 + 延迟 + 原因码，**不含 host / URL / token / 路径用户名**。
- **四语言文案**（`locales/*.json`）：新增 `layers` / `layerStatus` / `copyReport` / `copied` / `copyFailed` / `relogin`、`scopeTls` / `scopeApiKey`，以及全部新 `reasonCode` 文案。
- **`src/workbench/workbench-v2.css`**：`layer-list` / `layer-row` / `layer-status-label` / `layer-action` / `diagnostic-copy-button` 样式（全部走既有 token）。

### 测试与 CI

- `src/diagnostics/contract.test.ts`、`DiagnosticsView.test.tsx`：重写适配分层（含层级顺序、状态-原因自洽、脱敏断言、`api_key` 失败不改判线路可达）。
- `tests/work_packages/ru041/fixtures/connectivity-native.json`：升级为分层 + `schemaVersion: 2`（reachable / mixed / failed 三态）。
