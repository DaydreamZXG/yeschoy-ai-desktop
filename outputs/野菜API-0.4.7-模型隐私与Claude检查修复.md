# 野菜API 0.4.7：模型说明与 Claude 自检修复

范围：客户端补丁和内部安装包，不修改 NewAPI、服务器、真实账户或应用配置，不推送 GitHub、不发布 Release 或自动更新。

## 已查明的问题

模型选择器和模型价格页直接显示 NewAPI 模型 `description`。当前公开 `/api/pricing` 也返回了用户截图中的渠道标签；隐藏客户端文案并不等同于保护这个公开接口。

Claude Desktop 安装包的静态自检代码实际发送 `max_tokens: 1`、消息 `.`，不带 `stream` 字段；检查按 HTTP 成功状态判断，不要求返回文字。桥接层的非流式路径却用「有文字或工具调用」作为合法响应条件。合法空内容或仅思考内容因此可能被客户端改成 `502 invalid provider response`，而正常流式对话不会因这一条件返回 502。

该机制与截图一致，但没有读取真实请求返回体，不能把所有同文案 502 都归到这一种原因。官方文档也明确允许空内容结束响应：[Claude stop reasons](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons#empty-responses-with-end_turn)。

## 修改与验证目标

- 原生模型投影不传递未经审定的原始模型描述；选择器不显示或搜索描述，价格页也不再显示。保留完整模型 ID、计费分组、倍率与价格。
- 将消息结构与完成状态检查，与更强的接入验证证据分开。合法空内容、空白文字或思考内容正常返回，但不凭此宣称已验证接入。
- 鉴权失败、429、上游错误、损坏 JSON 和未完成消息继续保留失败。格式转换前也拒绝缺失或非对象的 `message`，避免将损坏响应变成正常空回答。不会制造回答、增加 token 预算、自动重试或改模型。
- 使用临时本机 HTTP 服务和合成凭据，按真实桥接路径验证；不读取真实密钥、聊天内容或配置，也不发送付费探针。
- 原有原生回归、界面测试、类型检查与生产构建均纳入 RU-040（承接 RU-039，修正当前版本验收来源）；实际结果以最新验证器记录为准，安装包结果另附构建回执。历史失败记录不改写。
- 客户端界面版本号直接读取 `package.json`，并检查原生清单、锁文件与生产资源均为 0.4.7，不再独立写死旧版本。

## 后端维护建议（本次未执行）

请技术同事清理公开模型价格接口的 `description`，只保留适合对用户展示的文案。内部上游、连接器、渠道和供应来源应保存在管理端字段，不应放到公开模型说明中。用户仍需看到对外计费分组和倍率；这不等于应公开供应链标签。

## 内测边界

新包版本为 0.4.7，保留旧版 0.4.6 安装包不覆盖。macOS 按已有证书签名、公证；Windows 仍是未签名交叉编译内测包，不能宣称 Windows 真机验证通过。未修改正在运行的 Claude 应用或清除它已有的错误提示；装新包并重新打开助手后，需要在 Claude 点击 Check again 验证。
