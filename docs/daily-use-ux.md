# 日常使用体验优化与验收范围

日期：2026-09-12。实现单元：RU-077 / WP-RU077-DAILY-USE。

这次交付是日常操作界面和前端任务状态的优化，不是一次全产品或 Windows/macOS 真机发布验收。主版与朋友版复用这些界面；没有改动两版的登录域名、更新通道或原生配置协议。

## 用户能感知的变化

- 首页先显示应用及“打开使用”“换模型与分组”“检查并修复”，账户数字移到下方可展开的“账户概览”。保留现有绿色视觉体系和系统字体，卡片底部操作对齐。
- “换模型与分组”只打开并聚焦模型选择器，不写配置、不重启应用。需要重写相同配置时使用单独的“重新应用当前设置”。
- 选了新默认模型时，主操作明确变为“使用所选模型”，确认草稿后再“保存并应用”。这期间不再保留容易误点的“打开使用”旧默认模型入口。其他常用模型的计费分组不随之改变；加入常用模型不等于更改默认模型。
- 应用正在运行时沿用原有原生接入流程：先提醒保存工作，再经用户确认退出、配置、重新打开。取消确认不写设置。此次没有另造一套进程控制或配置文件写入实现。
- 状态读取、接入失败和打开失败共用恢复提示结构，保留安全错误原因和具体下一步。“检查并修复”先读取状态，不偷偷恢复或覆盖配置。
- 明确区分“配置已保存”“已请求打开 / 已检查启动”和“实际请求记录”。没有请求记录时不声称已验证模型连通。直连配置不再统一显示“必须保持野菜运行”。

## 状态隔离与解耦

`useActivationTask.ts` 单独持有接入任务、请求 ID、进度和取消状态；接入页面负责草稿选择和展示，继续调用已有原生接口。

- 同步 in-flight 防护拦截立即重复点击；重置草稿不能擦掉仍在运行的任务和取消 ID。
- 取消失败可以重试；旧取消回复不影响新任务；卸载页面后不发布旧完成回调。
- 从首页进入同一个应用也带递增意图编号，解决“页内切过应用，回首页再选原应用却没有切回来”。
- 进行中的跨应用切换排队到任务结束；切换后清理前一应用的结果和重启提示，不遮住目标应用已经确认的“打开使用”。

这是针对接入任务的一次拆分，不代表整个接入页面、账户服务或安装服务已完成全面重构。

### 离线浏览器复核

```sh
pnpm exec vite --config scripts/qa/daily-use/vite.config.mjs
```

预览地址 `http://127.0.0.1:4197/`。`?state=repair` 模拟设置已变化，`?state=unavailable` 模拟连接状态读取失败。数据明确标为“演示账户 · 非真实数据”；所有原生调用被专用内存 fixture 替换，不访问真实账户、不读写应用配置、不启动或退出已安装应用。

本轮在浏览器中实际操作并复核了：

- 首页应用优先、账户概览默认收起；1280×900 深色模式同排卡片底部一致，无横向溢出。
- 首页“换模型与分组”展开并聚焦选择器，输入 `5.6`、方向键和回车选中模型。
- 选择另一已配置模型后，主按钮为“使用所选模型”且旧“打开使用”入口消失；确认草稿后变为“保存并应用”。
- 320×800 下保存 / 退出确认框完整可见；模拟确认后无残留 dialog，`body` 的 `pointer-events` 为 `auto`，主操作恢复，首页显示新默认模型和两个常用模型。
- 打开操作仅显示“已发送打开请求”，不会声称加载或模型请求已经成功。
- 设置变化时显示“检查并修复”，进入后不自动弹出退出确认；读取失败时显示“接入状态待确认”和重试入口，不误报为未接入。
- 窄屏应用栏和“模型与价格”标题不再挤成窄列；320 像素页面宽度等于滚动宽度。临时预览尺寸覆盖已恢复。最终浏览器检查未见控制台 error。

离线预览构建只用于浏览器检查，不生成安装包。构建仍提示现有浏览器兼容数据库较旧和主包体积较大，未以静默升级依赖或调高阈值掩盖警告。
