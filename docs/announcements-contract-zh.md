# 桌面助手公告：服务端接口说明

这份文档给后端同学看：桌面助手的「公告」怎样从服务端读，各字段在客户端上分别起什么作用。

0.4.26 之后的客户端版本支持本文全部字段；更早的版本只认 `id`、`title`、`body`、`severity`、`publishedAtEpochMs`，其余字段会被忽略，不会出错。只要服务端还没上线，客户端就不显示公告入口，所以**哪一边先发布都不会出问题**。

---

## 1. 宣告公告地址：bootstrap 加一个字段

客户端登录后会请求 `GET {线路域名}/api/desktop/v2/bootstrap`，域名有两条线路：

- `https://yeschoy.com`
- `https://api.yeschoy.com`

在返回的 `data` 里加一个**可选**字段 `announcements_path`：

```json
{
  "success": true,
  "data": {
    "...": "现有字段不变",
    "announcements_path": "/api/desktop/v2/notices"
  }
}
```

- 不返回这个字段，或者返回空串：客户端不显示「公告」入口。
- 值必须是本站的**相对路径**：以 `/` 开头，长度不超过 256，只能包含字母、数字、`/ - _ .`，不能出现 `..`。不满足这些条件的值会被客户端当作没有。
- 两条线路的 bootstrap 都要返回，因为用户可能在任一条线路上登录。

## 2. 公告接口

```
GET {线路域名}{announcements_path}
Authorization: Bearer <桌面会话 access token>
Accept: application/json
```

- 鉴权方式和 `/api/user/self` 一样，用的是同一个桌面会话令牌。可以按用户或分组返回不同的公告。
- 响应头必须是 `Content-Type: application/json`，响应体不超过 2 MB。
- 返回非 2xx 时，客户端只当作「暂时读不到」：已经显示的公告保留，只提示可以重试，**不会影响登录和接入**。

### 响应格式

```json
{
  "success": true,
  "data": {
    "notices": [
      {
        "id": "recharge-2026-10",
        "title": "国庆充值加赠 20%",
        "body": "10 月 1 日至 7 日，单笔充值满 100 元加赠 20%。\n赠送额度即时到账。",
        "severity": "info",
        "publishedAtEpochMs": 1759276800000,
        "expiresAtEpochMs": 1759852800000,
        "banner": true,
        "action": { "kind": "wallet", "label": "去充值" }
      }
    ]
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 建议必填 | 公告的唯一标识，最长 64 个字符。客户端靠它记住「这条读过了」。**同一条公告的 id 不要变**；想让所有人重新看到一次，就换一个新 id。缺 id 时客户端用标题代替；id 重复时只保留第一条。 |
| `title` | 必填 | 标题，最长 120 个字符。标题为空的公告会被丢弃。 |
| `body` | 可选 | 正文，纯文本，最长 2000 个字符。用 `\n` 换行分段。**不支持 HTML、Markdown 或链接**，写了也会原样显示成文字。首页横幅只显示正文的第一段。 |
| `severity` | 可选 | 取 `"info"`（默认）或 `"warning"`。`warning` 用琥珀色显示，适合涨价、线路下线、维护这类需要用户注意的通知；活动推广用 `info`。 |
| `publishedAtEpochMs` | 可选 | 发布时间，毫秒时间戳，显示为日期。 |
| `expiresAtEpochMs` | 可选 | 截止时间，毫秒时间戳。过了这个时间，客户端自动不再显示，不用等运营去后台撤；公告卡片上还会显示「截止 X 月 X 日」。填 `0` 或不填表示不过期。 |
| `banner` | 可选 | 填 `true` 时，用户还没读过这条公告，就在「我的应用」首页顶部显示一条横幅。同时有多条时只显示列表里**最靠前**的一条。用户点了横幅上的按钮、点了「查看全部公告」、关掉横幅，或者打开过公告页，都算读过，之后不再显示。 |
| `action` | 可选 | 公告上的按钮，详见下一节。 |

- 列表顺序就是显示顺序，客户端不会重新排序。请把最重要的放在前面。
- 一次最多显示 30 条，多出来的会被忽略。
- 控制字符和双向文字覆盖字符会被过滤掉。

### `action`：按钮

每条公告最多一个按钮，`label` 是按钮上的文字，最长 16 个字符。按钮只有两种：

```json
{ "kind": "wallet", "label": "去充值" }
```

- 打开该账户的充值（钱包）页，和客户端里其他「充值」按钮去的是同一个地方。**充值活动请优先用这一种。**

```json
{ "kind": "link", "label": "查看活动细则", "url": "https://yeschoy.com/events/2026-10" }
```

- 在系统浏览器里打开一个网页。为了防钓鱼，`url` 必须同时满足：
  - 使用 `https`；
  - 域名是 `yeschoy.com`、它的任意子域名（`*.yeschoy.com`），或 `ai.yeschoy.io`；
  - 不带端口号，也不带用户名或密码；
  - 长度不超过 2048。
- 可以带查询参数，例如 `?utm_source=desktop`。

不满足上面条件的 `action`，或者 `kind` 不是这两种的，客户端会**只去掉按钮**，公告本身照常显示。按钮的目标地址只保存在客户端的原生层，界面层拿不到，所以网页内容没法利用它打开任意地址。

## 3. 客户端什么时候读

- 登录成功后读一次。
- 之后每 30 分钟读一次。
- 窗口重新回到前台、并且距离上次读取已超过 5 分钟时，再读一次。

所以新发布的公告，最晚大约 30 分钟后就能被正在使用的用户看到。这个接口的请求量约等于「在线用户数 × 每小时 2 次」，建议在服务端做缓存。

「读过哪些」只存在用户本机，不回传服务端，所以换一台电脑会再看到一次。

## 4. 例子：充值活动

```json
{
  "id": "recharge-2026-10",
  "title": "国庆充值加赠 20%",
  "body": "10 月 1 日至 7 日，单笔充值满 100 元加赠 20%。\n赠送额度即时到账，可在用量账单里查看。",
  "severity": "info",
  "publishedAtEpochMs": 1759276800000,
  "expiresAtEpochMs": 1759852800000,
  "banner": true,
  "action": { "kind": "wallet", "label": "去充值" }
}
```

用户看到的效果：

1. 首页顶部出现一条横幅，显示标题、正文第一句，以及「去充值」「查看全部公告」和关闭三个按钮。
2. 侧边栏「公告」入口旁出现未读数。
3. 点「去充值」直接打开充值页，横幅随即消失。
4. 10 月 7 日之后，这条公告自动不再显示。

## 5. 上线前自测

- [ ] 两条线路的 bootstrap 都返回了 `announcements_path`。
- [ ] 用桌面会话令牌请求公告接口，返回 200 和 `application/json`。
- [ ] 每条公告的 `id` 唯一，并且不会随时间变化。
- [ ] `link` 类按钮的 URL 是 https，且在允许的域名内。
- [ ] 活动类公告填了 `expiresAtEpochMs`。
- [ ] 在桌面助手里检查：侧边栏出现「公告」和未读数，首页出现横幅，按钮能打开正确的页面。
