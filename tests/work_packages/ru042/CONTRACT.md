# RU-042: model identity, model sets, request errors and graceful exit

User authority: 2026-09-05, “这是失败时的错误详情，其他按你的想法完善一下”. No packaging, publishing, server change, real credential/config access or paid verification during development.

## Target, not a claim of completion

Each tool has one explicit set of unique real model IDs, a default member, and a fixed billing group per member. One model ID cannot ambiguously mean two groups. First-party origin remains selected per tool. Existing single-model records remain readable; a new activation migrates only that tool. No automatic account-wide model enrollment or cross-group fallback. Only the selected default is actively verified during activation; additional members are labeled configured/not tested. Native request observations never prove the underlying weights or vendor identity.

All newly configured tools use a tool-authenticated loopback gateway so requests can select the correct group/key. UI explicitly discloses the assistant must stay in the background. Stable local tokens allow in-flight requests to pin their route while new requests use the updated set. No rewrite of assistant replies or blanket replacement of system prompts. Claude profile names and model menus use real model IDs, not Sonnet labels. Native defaults may change to another registered member without invalidating connection integrity. Initial configuration/catalog changes may still require a vendor restart; daily switching among existing members uses its native menu or command.

## Exit owner interface and safety

`ShutdownCoordinator` with `admit_operation`, `request_shutdown`, `wait_quiescent(deadline)`, `register_stop`, `stop_registered(deadline)`; `OperationPermit::{is_cancelled,cancelled,cancel_safe}`. Expose a single process-global coordinator accessor so activation/account/open/restore can share it. Only explicit confirmation requests shutdown. Window X opens a globally mounted choice host; background minimizes deliberately, cancel keeps window, exit stops owned runtimes only. No external tool process killing.

Permit covers each operation through local safe cleanup. Cancel only lock wait, discovery, read-only model queries, and verification; never drop a token-create/refresh POST or local file/key transaction. Finish already-issued bounded account mutations, then rollback locally and release permit; skip restarting old gateways during shutdown. Account HTTP already has a 20-second per-call bound; use that same interval for a recoverable “finishing operation” status, not forced transaction abort. Once quiescent, registered runtime stops share the existing Codex 2-second grace bound, followed by owned task/process cancellation and process exit. UI must not remain in a permanently disabled modal; repeated exit is idempotent. A delayed remote cleanup must not be represented as completed.
